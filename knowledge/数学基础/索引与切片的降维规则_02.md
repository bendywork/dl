# 索引与切片的降维规则

## 📌 核心问题
numpy/PyTorch 中，对张量用具体数字索引 vs 切片，结果形状不同，为什么？

## 🌱 根源与动机
对一个三维张量 token_embs (1, 5, 128)：
- token_embs[:, 0, :] 结果是 (1, 128)
- token_embs[:, 0:1, :] 结果是 (1, 1, 128)
两者看起来都是"取第0个"，但形状不同，原因在于索引和切片的语义不同。

## 📐 理论推导

核心规则：
- 具体数字索引 → 降维，该维度消失
- 切片（: 或 a:b）→ 不降维，该维度保留

对比：
```
token_embs.shape  # (1, 5, 128)

token_embs[:, 0, :]    # 0是具体数字 → 维度1消失 → (1, 128)
token_embs[0, :, :]    # 0是具体数字 → 维度0消失 → (5, 128)
token_embs[0, 0, 0]    # 三个具体数字 → 全消失 → 标量

token_embs[:, 0:1, :]  # 0:1是切片   → 维度1保留 → (1, 1, 128)
token_embs[:, :, :]    # 全是切片    → 不变 → (1, 5, 128)
```

## 💡 关键理解

类比"书"的比喻：
- 维度0 = 第几本书（batch）
- 维度1 = 第几页（token位置）
- 维度2 = 页面内容（特征向量）

token_embs[:, i, :] = 取所有书的第 i 页，"第几页"这个维度被消费掉了，结果只剩"哪本书"和"页面内容"。

索引是"点"，切片是"范围"：
- 索引取出一个点 → 那个轴消失
- 切片取出一段 → 那个轴还在，只是可能变短

## 🔧 代码实现

```python
import torch

token_embs = torch.randn(1, 5, 128)

# 索引 → 降维
print(token_embs[:, 0, :].shape)    # (1, 128)
print(token_embs[0, :, :].shape)    # (5, 128)
print(token_embs[0, 0, 0].shape)    # torch.Size([])  标量

# 切片 → 不降维
print(token_embs[:, 0:1, :].shape)  # (1, 1, 128)
print(token_embs[:, 1:3, :].shape)  # (1, 2, 128)

# 实际应用：想保留维度时用切片代替索引
x = token_embs[:, 0, :]    # (1, 128)   维度消失
y = token_embs[:, 0:1, :]  # (1, 1, 128) 维度保留
```

## ⚠️ 易错点与常见误解

1. token_embs[:, 0, :] 和 token_embs[:, 0:1, :] 取的数据一样，但形状不同 → 具体数字降维，切片不降维
2. 需要保留维度时（比如后续做矩阵乘法要求特定维度数），用 0:1 而不是 0
3. 多个具体数字索引可以同时降多个维度

## 🔗 知识延伸
- 与 unsqueeze/squeeze 的关系：token_embs[:, 0, :].unsqueeze(1) 可以把消失的维度加回来，等价于 token_embs[:, 0:1, :]
- 与矩阵乘法的关系：降维后形状变化，可能影响后续 @ 运算的维度匹配
