# DL 模型参数命名规范

## 📌 核心问题
> RNN/LSTM 的权重矩阵命名为什么用 W 和 U 两组字母？工程代码中应该如何命名更清晰？

## 🌱 根源与动机

### 1. 为什么需要两组权重矩阵？
RNN/LSTM 的每个门都有两个输入来源：
- 隐藏状态 h_{t-1}（上一时刻的输出）
- 当前输入 x_t

因此每个门需要两套权重矩阵分别处理这两个输入。

### 2. 论文中的 W / U 约定
在学术论文中，习惯用：
- W（或 W_h）：乘以隐藏状态 h_{t-1} 的权重矩阵
- U（或 W_x）：乘以输入 x_t 的权重矩阵

以 LSTM 遗忘门为例：
f_t = σ(W_f · h_{t-1} + U_f · x_t + b_f)

U 的选择本质上是历史惯性：
- W 已经被用于隐藏状态权重
- T 被时间步下标占用
- V 在部分文献中用于偏置或价值函数
- U 是 W 附近未被占用的字母，因此"空降"到输入权重位置

U 并不代表任何英文单词的缩写，纯粹是字母表排位上的空位选择。

### 3. 下标 t 的歧义问题
如果尝试用 W_ft 代替 U_f（其中 f=遗忘门，t=输入），会产生歧义：
- t 在序列模型中已被约定为"时间步"（time step）
- W_ft 看起来像"遗忘门在时间步 t 的权重"，而不是"遗忘门对输入的权重"

更清晰的统一写法是用第二下标区分乘的对象：
| 符号 | 含义 |
|------|------|
| W_{f,h} | 遗忘门 × 隐藏状态的权重 |
| W_{f,x} | 遗忘门 × 输入的权重 |
| W_{i,h} | 输入门 × 隐藏状态的权重 |
| W_{i,x} | 输入门 × 输入的权重 |
| W_{o,h} | 输出门 × 隐藏状态的权重 |
| W_{o,x} | 输出门 × 输入的权重 |
| W_{g,h} | 候选状态 × 隐藏状态的权重 |
| W_{g,x} | 候选状态 × 输入的权重 |

所有权重统一用 W，靠第二下标区分乘的对象，消除了 U 的语义模糊。

### 4. 为什么论文坚持用 W/U 而非更描述性的命名？
- 排版密度：U_f · x_t 比 W_{f,x} · x_t 短一截，LSTM 有 4 个门各 2 组权重，公式紧凑性差距明显
- 视觉区分：W vs U 一眼区分"隐状态权重 / 输入权重"，下标区分需要多读一层
- 传统延续：Hochreiter & Schmidhuter (1997) 原始 LSTM 论文使用此约定，后续论文和教科书跟进形成惯例

## 📐 三种命名体系对比

| 体系 | 遗忘门输入权重 | 遗忘门隐状态权重 | 适用场景 |
|------|---------------|-----------------|---------|
| 论文 W/U | U_f | W_f | 学术论文、数学公式 |
| 双下标统一 | W_{f,x} | W_{f,h} | 教学材料、技术博客 |
| PyTorch 风格 | weight_ih_l0 | weight_hh_l0 | 工程代码 |

### PyTorch LSTM 参数命名详解
PyTorch 的 nn.LSTM 使用 ih / hh 命名：
- weight_ih_l0：input-to-hidden，第0层 → 对应 U
- weight_hh_l0：hidden-to-hidden，第0层 → 对应 W
- bias_ih_l0：input-to-hidden 偏置 → 对应 b_U
- bias_hh_l0：hidden-to-hidden 偏益 → 对应 b_W

其中 ih = input-to-hidden，hh = hidden-to-hidden，比 U/W 清晰得多。

## 💡 关键理解

数学公式和代码的命名逻辑不同：
- 数学公式追求简短（单字母 + 下标），排版紧凑优先
- 工程代码追求可读（描述性命名），见名知意优先
- 不要把论文符号直接搬进代码，也不要期望代码命名在公式里好看

## 🔧 代码实现

### 论文风格命名（不推荐用于代码）

```python
# ❌ 论文符号直接搬进代码，U 语义不明
class LSTMCellPaper(nn.Module):
    def __init__(self, input_size, hidden_size):
        super().__init__()
        # 遗忘门
        self.U_f = nn.Linear(input_size, hidden_size, bias=False)   # x_t → f_t
        self.W_f = nn.Linear(hidden_size, hidden_size, bias=False)  # h_{t-1} → f_t
        self.b_f = nn.Parameter(torch.zeros(hidden_size))
        # ... 其他门类似
```

### 描述性命名（推荐）

```python
# ✅ 见名知意，清楚每个权重的作用
class LSTMCellDescriptive(nn.Module):
    def __init__(self, input_size: int, hidden_size: int):
        super().__init__()
        self.hidden_size = hidden_size

        # 遗忘门
        self.forget_gate_x = nn.Linear(input_size, hidden_size, bias=False)   # 输入 → 遗忘门
        self.forget_gate_h = nn.Linear(hidden_size, hidden_size, bias=False)  # 隐状态 → 遗忘门
        self.forget_gate_bias = nn.Parameter(torch.zeros(hidden_size))

        # 输入门
        self.input_gate_x = nn.Linear(input_size, hidden_size, bias=False)
        self.input_gate_h = nn.Linear(hidden_size, hidden_size, bias=False)
        self.input_gate_bias = nn.Parameter(torch.zeros(hidden_size))

        # 候选状态
        self.candidate_x = nn.Linear(input_size, hidden_size, bias=False)
        self.candidate_h = nn.Linear(hidden_size, hidden_size, bias=False)
        self.candidate_bias = nn.Parameter(torch.zeros(hidden_size))

        # 输出门
        self.output_gate_x = nn.Linear(input_size, hidden_size, bias=False)
        self.output_gate_h = nn.Linear(hidden_size, hidden_size, bias=False)
        self.output_gate_bias = nn.Parameter(torch.zeros(hidden_size))

    def forward(self, x_t: torch.Tensor, h_prev: torch.Tensor, c_prev: torch.Tensor):
        f = torch.sigmoid(
            self.forget_gate_x(x_t) + self.forget_gate_h(h_prev) + self.forget_gate_bias
        )
        i = torch.sigmoid(
            self.input_gate_x(x_t) + self.input_gate_h(h_prev) + self.input_gate_bias
        )
        g = torch.tanh(
            self.candidate_x(x_t) + self.candidate_h(h_prev) + self.candidate_bias
        )
        o = torch.sigmoid(
            self.output_gate_x(x_t) + self.output_gate_h(h_prev) + self.output_gate_bias
        )

        c_t = f * c_prev + i * g
        h_t = o * torch.tanh(c_t)
        return h_t, c_t
```

### 使用 PyTorch 官方 LSTM（最简洁）

```python
# ✅ 生产环境直接用 nn.LSTM，参数命名已经是 ih/hh 风格
lstm = nn.LSTM(input_size=128, hidden_size=256, num_layers=2, batch_first=True)

# 查看参数命名
for name, param in lstm.named_parameters():
    print(f"{name}: {param.shape}")
# weight_ih_l0: [1024, 128]   → 4个门 × 256 = 1024，输入权重
# weight_hh_l0: [1024, 256]   → 4个门 × 256 = 1024，隐状态权重
# bias_ih_l0:   [1024]
# bias_hh_l0:   [1024]
# weight_ih_l1: [1024, 256]   → 第2层，输入来自第1层隐状态
# ...
```

## ⚠️ 易错点与常见误解

1. **U 是某个词的缩写？** 不是。U 不代表 Unit / Input / Update 等任何单词，纯粹是字母排位空位选择。
2. **论文命名和代码命名应该一致？** 不应该。两者服务于不同目的：公式求紧凑，代码求可读。
3. **PyTorch 的 weight_ih 就是 U？** 对，ih = input-to-hidden 对应论文的 U，hh = hidden-to-hidden 对应论文的 W。但 PyTorch 把 4 个门的权重拼接成一个大矩阵（1024 = 4×256），内部不再按门拆分。
4. **所有 RNN 变体都用 W/U 约定？** 不一定。GRU 论文有时用 W_z / W_r / W_h 统一表示（不区分输入和隐状态），具体看论文符号表。

## 🔗 知识延伸

- RNN 参数共享：同一组 W/U 在所有时间步共享，这是参数效率的关键
- GRU 的参数命名：只有重置门和更新门，命名更简单
- Transformer 的参数命名：W_Q / W_K / W_V，所有权重统一用 W + 功能下标，不存在 U 的问题
- 注意力机制中的 W 与 LSTM 中的 W 含义不同：前者是投影矩阵，后者是循环权重
