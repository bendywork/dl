# 自编码器与机器翻译

## 📌 核心问题
> 自编码器的思想如何应用到机器翻译？翻译的完整流程是什么？

## 🌱 根源与动机

自编码器核心思想：**压缩 → 重建**。机器翻译本质也是这个过程——把原语言"压缩"成语义表示，再"重建"成目标语言。这就是 Seq2Seq（Encoder-Decoder）架构的直觉来源。

## 📐 完整翻译流程

```
输入: "我爱你"

Step 1: 分词
  → ["我", "爱", "你"]

Step 2: Embedding（查词向量表）
  → [v_我, v_爱, v_你]  (每个词变成 d 维向量)

Step 3: Encoder（读入理解）
  → 输出每个位置的隐状态 [h1, h2, h3]
  → 或压缩成上下文向量 c = h3（最后一步）

Step 4: Decoder（逐步生成）
  输入: <SOS>（开始符）
  → Attention动态回看 [h1,h2,h3]，计算当前关注权重
  → 生成隐状态 s1
  → Linear(s1) → 词表大小的向量（比如50000维）
  → Softmax → 概率分布
  → argmax → "I"

  输入: "I"（上一步生成的词）
  → 生成 "love" → 生成 "you" → 生成 <EOS>（停止）

输出: "I love you"
```

## 💡 关键理解

### 自编码器 vs 机器翻译对应关系

| 自编码器 | 机器翻译 |
|---------|---------|
| Encoder压缩输入 | Encoder读入原文，输出隐状态 |
| 瓶颈层z（隐向量） | 上下文向量c / Attention加权向量 |
| Decoder重建输出 | Decoder逐词生成目标语言 |
| 输出和输入同语言 | 输出是另一种语言 |

### 解码阶段：不是"查找"，是"逐步生成"

解码器不是把压缩向量去目标语言词表里查最相似的词，而是：

```
Decoder隐状态 h_t
    ↓
Linear层（h_size → vocab_size）
    ↓
Softmax → 每个词的概率分布
    ↓
argmax → 当前步最可能的词
    ↓
把这个词作为下一步的输入（自回归）
```

**自回归**：每次生成的词会作为下一步的输入，逐步展开，直到生成 `<EOS>`。

### Weight Tying（权重共享）

解码器的 Linear 层权重**有时和 Embedding 矩阵共享**：
- 正向：词 → 向量（Embedding 查表）
- 反向：向量 → 词（Linear 投影 + Softmax）

同一个矩阵，一正一反两个方向——这时"用向量在词表中找语义"的直觉是完全正确的。

## ⚠️ 易错点与常见误解

1. **"解码就是用压缩向量去目标语言矩阵里找语义最近的词"** → 不准确。解码是逐步自回归生成，每步都经过 Decoder 网络计算新隐状态，再 Linear → Softmax 选词；不是一次静态查找
2. **"Attention是在目标语言Embedding矩阵里查"** → 不对。Attention 查的是 Encoder 每步的输出隐状态（动态计算的），不是静态词向量矩阵
3. **"翻译是一次性输出所有词"** → 不对。是自回归逐词生成，每个词依赖前面已生成的词（Decoder 的输入是上一步的输出）
4. **自编码器和翻译用的Encoder-Decoder的区别**：普通自编码器输入输出同语言（重建），翻译的Encoder-Decoder输出是另一种语言；结构相同，目标不同
