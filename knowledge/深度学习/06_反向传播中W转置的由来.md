# 反向传播中 W^T 的由来

## 📌 核心问题

> 前向传播：`z = W @ x`，W 是 m×n 矩阵
> 反向传播求 `∂L/∂x` 时，为什么出现 `Wᵀ` 而不是 `W`？

## 🌱 根源与动机：从标量链式法则到向量链式法则

### 第一步：标量链式法则（你已经会的）

```
L 是标量
y = w · x  （w, x, y 都是标量）
∂L/∂x = ∂L/∂y · ∂y/∂x = ∂L/∂y · w
```

没有转置，因为一切都是标量。

### 第二步：多个标量（关键的跳跃）

现在 y 不再是一个标量，而是**两个标量**：

```
y₁ = w₁₁·x₁ + w₁₂·x₂
y₂ = w₂₁·x₁ + w₂₂·x₂
```

x 影响 y₁ 和 y₂ **两条路**，所以 x₁ 对 L 的贡献必须**两条路都算**：

```
∂L/∂x₁ = ∂L/∂y₁ · ∂y₁/∂x₁  +  ∂L/∂y₂ · ∂y₂/∂x₁
        = ∂L/∂y₁ · w₁₁       +  ∂L/∂y₂ · w₂₁
```

**看到没有？w 的第二个下标翻转了——从 w₁₂ 变成了 w₂₁。这就是转置的物理来源。**

### 第三步：写成矩阵形式——转置必然出现

把上面展开式用矩阵写：

```
∂L/∂x₁ = w₁₁·∂L/∂y₁ + w₂₁·∂L/∂y₂
∂L/∂x₂ = w₁₂·∂L/∂y₁ + w₂₂·∂L/∂y₂
```

即：

```
┌ ∂L/∂x₁ ┐     ┌ w₁₁  w₂₁ ┐   ┌ ∂L/∂y₁ ┐
│         │  =  │           │ · │         │
└ ∂L/∂x₂ ┘     └ w₁₂  w₂₂ ┘   └ ∂L/∂y₂ ┘
```

右边那个矩阵，和前向的 W 比较：

```
W  = ┌ w₁₁  w₁₂ ┐     Wᵀ = ┌ w₁₁  w₂₁ ┐
     └ w₂₁  w₂₂ ┘          └ w₁₂  w₂₂ ┘
```

**反向传播用到的恰好是 Wᵀ。**

### 一句话总结

> **转置出现的本质原因：x 的每个分量通过 W 的不同行（多条路径）影响了 y 的多个分量，链式法则要求把这些路径的贡献加起来，加法方向恰好对应 W 的列方向 = Wᵀ 的行方向。**

## 📐 理论推导

### 标量展开 → 矩阵形式

```
∂L/∂x₁ = w₁₁·∂L/∂y₁ + w₂₁·∂L/∂y₂
∂L/∂x₂ = w₁₂·∂L/∂y₁ + w₂₂·∂L/∂y₂
```

写成矩阵：
```
∂L/∂x = [w₁₁  w₂₁]   [∂L/∂y₁]     = Wᵀ · ∂L/∂y
         [w₁₂  w₂₂] · [∂L/∂y₂]
```

### 维度论证

```
前向：y(m,) = W(m,n) · x(n,)
反向：∂L/∂x(n,) = ? · ∂L/∂y(m,)

(n,) = ? · (m,)  →  ? 必须是 (n,m)

W 是 (m,n)，Wᵀ 恰好是 (n,m)
维度上唯一可能就是 Wᵀ，这是数学必然，不是约定
```

### Jacobian 视角

对 y = Wx，Jacobian J = ∂y/∂x = W (m×n)，其中 Jᵢⱼ = ∂yᵢ/∂xⱼ = Wᵢⱼ

链式法则向量版：
```
∂L/∂xⱼ = Σᵢ (∂L/∂yᵢ) · (∂yᵢ/∂xⱼ)
        = Σᵢ vᵢ · Jᵢⱼ
        = (Jᵀ · v)ⱼ
```

本质：梯度是 **VJP（Vector-Jacobian Product）**，把上游向量乘到 Jacobian 的**列**上，矩阵乘向量默认乘**行**，所以要转置。

## 💡 关键理解

| 类比 | 说明 |
|------|------|
| 水管网络 | 前向：水从 x 流向 y（W 控制分流比例）；反向：压力从 y 传回 x（Wᵀ 控制汇聚比例） |
| 翻译 | 前向 W 把 x 的语言"翻译"成 y；反向 Wᵀ 把 y 的梯度"翻译回" x 的语言 |
| 信号传播 | W 告诉每个 x 分量影响了哪些 y；Wᵀ 告诉每个 x 分量要收集哪些 y 的反馈 |

**一句话**：转置出现是因为 x 的每个分量通过多条路径影响多个 y，链式法则沿路径求和时，下标翻转 = 矩阵转置。

## 🔧 代码实现

详见：`stage02/backprop_w_transpose_demo.py`

核心验证：
```python
W = np.array([[1., 2.], [3., 4.]])
x = np.array([5., 6.])
dL_dy = np.array([0.1, 0.2])

# 手动标量展开
dL_dx1 = dL_dy[0]*W[0,0] + dL_dy[1]*W[1,0]  # 注意 W[1,0] 不是 W[0,1]
dL_dx2 = dL_dy[0]*W[0,1] + dL_dy[1]*W[1,1]

# 矩阵形式——恰好 = Wᵀ @ dL_dy
dL_dx = W.T @ dL_dy  # 和标量展开完全一致
```

## ⚠️ 易错点与常见误解

1. **"转置是约定/记号"** → 错。转置是标量展开的必然结果，不是人为定义的记号
2. **"∂y/∂x = W，所以 ∂L/∂x = W · ∂L/∂y"** → 错。这是混淆了 Jacobian 和梯度的乘法方向。J=W 乘在"行"上，梯度需要乘在"列"上，所以必须转置
3. **"只有方阵才转置"** → 错。非方阵更明显——W(3×2) 反向必须用 Wᵀ(2×3)，维度才能对上
4. **"Wᵀ 出现是因为求导对 W 取了转置"** → 不精确。Wᵀ 出现是因为链式法则沿**多条路径**求和，路径的汇聚方向恰好对应转置，和"W本身被求导"无关
5. **混淆 JVP 和 VJP**：JVP（Jacobian-Vector Product）= J·v，用于前向模式自动微分；VJP（Vector-Jacobian Product）= v·J = Jᵀ·v，用于反向模式（反向传播）。深度学习用反向模式，所以出现转置
