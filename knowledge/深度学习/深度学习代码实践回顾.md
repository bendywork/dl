# 深度学习代码实践回顾

## 1. 为什么创建网络必须基于 torch.nn.Module？

### 从代码出发

```python
class ClassifyNetwork(nn.Module):          # ← 必须继承 nn.Module
    def __init__(self, in_features, num_classes):
        super().__init__()                  # ← 必须调用父类初始化
        self.features = nn.Sequential(...)  # ← 子模块注册
        self.classify = nn.Linear(8, num_classes)

    def forward(self, x):                   # ← 必须实现前向逻辑
        features = self.features(x)
        score = self.classify(features)
        return score
```

看似简单的三行（继承、super、forward），背后是 nn.Module 提供的一整套基础设施。**不用 nn.Module，你就得自己从零实现这些。**

---

### nn.Module 到底提供了什么？

#### 一、参数自动注册与管理

```python
self.classify = nn.Linear(8, 2)
# 这一行背后发生了什么？
# 1. nn.Linear 创建了 weight (shape [2,8]) 和 bias (shape [2])
# 2. 因为 self.classify 是 nn.Module 的属性，nn.Module 自动将它的参数注册到全局参数表
# 3. 调用 net.parameters() 就能拿到所有参数
```

**如果没有 nn.Module**，你需要手动追踪每个参数：

```python
# 手动管理的噩梦
self.w1 = torch.randn(8, 2, requires_grad=True)  # 自己创建
self.b1 = torch.randn(2, requires_grad=True)       # 自己创建
self.w2 = torch.randn(8, 8, requires_grad=True)    # 自己创建
self.b2 = torch.randn(8, requires_grad=True)        # 自己创建
# 优化器要手动传入所有参数：
opt = optim.SGD([self.w1, self.b1, self.w2, self.b2], lr=0.01)
# 加10层？50层？手动维护参数列表是灾难
```

**nn.Module 的机制**：`self.xxx = nn.Linear(...)` 时，`__setattr__` 被触发，自动检测赋值的对象是否是 nn.Module/nn.Parameter，如果是就注册到 `_modules` / `_parameters` 字典中。`parameters()` 方法递归遍历所有子模块，收集全部参数。

#### 二、自动求导链路的建立

```python
score = net(batch_x_train)    # 前向传播
loss = loss_fn(score, batch_y_train)
loss.backward()               # 反向传播，自动计算所有参数的梯度
```

**nn.Module 保证**：
- 所有注册的参数都有 `requires_grad=True`
- 前向过程中 PyTorch 自动记录计算图
- `backward()` 自动沿计算图回传梯度到每个参数

**如果没有 nn.Module**：你需要手动确保每个参数参与计算图、手动调用 `.backward()`、手动收集梯度。

#### 三、train/eval 模式切换

```python
net.train()   # 训练模式
net.eval()    # 推理模式
```

**为什么需要模式切换？** 因为某些层在训练和推理时行为不同：

| 层 | 训练模式 | 推理模式 |
|---|---------|---------|
| **Dropout** | 随机丢弃一部分神经元 | 不丢弃，但输出乘以保留概率（补偿训练时的缩放） |
| **BatchNorm** | 用当前 batch 统计均值/方差，并更新 running_mean/var | 用积累的 running_mean/var，不更新 |

代码中的体现：

```python
def forward(self, x):
    ...
    if self.training:        # ← nn.Module 提供的 self.training 属性
        return score         # 训练时返回原始 score（配合 CrossEntropyLoss）
    return torch.softmax(score, dim=1)  # 推理时返回概率
```

`net.train()` 将 `self.training` 设为 `True`，`net.eval()` 设为 `False`，同时递归地对所有子模块调用。**没有 nn.Module 你就得自己维护这个状态并手动传递给每一层。**

#### 四、模型保存与加载

```python
# 保存
torch.save({'net': net, 'net_param': net.state_dict()}, 'model.pkl')

# 加载
obj = torch.load('model.pkl')
net = obj['net']          # 整个模型（结构+参数）
net.eval()
```

`state_dict()` 是 nn.Module 提供的方法，返回一个 OrderedDict，包含所有参数的名称和张量值。这个结构让模型可以独立于代码进行序列化/反序列化。

**如果没有 nn.Module**：你需要自己实现"把所有参数收集成字典"和"从字典恢复所有参数"的逻辑。

#### 五、模块嵌套与 Sequential 容器

```python
self.features = nn.Sequential(
    nn.Linear(2, 8),    # 第1层
    nn.ReLU(),          # 激活
    nn.Linear(8, 8),    # 第2层
    nn.ReLU()           # 激活
)
```

`nn.Sequential` 是 nn.Module 的子类，自动将多个子模块按顺序串联：
- 前向时依次调用每个子模块，上一个的输出是下一个的输入
- 参数自动注册到父模块
- `net.features[0]` 就能访问第一个 Linear 层

**嵌套结构**：
```
ClassifyNetwork (nn.Module)
  ├── features (nn.Sequential → 也是 nn.Module)
  │     ├── 0: Linear(2, 8)    → weight, bias
  │     ├── 1: ReLU
  │     ├── 2: Linear(8, 8)    → weight, bias
  │     └── 3: ReLU
  └── classify (nn.Linear → 也是 nn.Module)
        └── weight, bias
```

`net.parameters()` 递归遍历这棵树，收集到所有参数（ReLU无参数，实际4个参数张量）。

#### 六、Hook 机制——调试与中间层监控

```python
handle = net.features.register_forward_hook(_hook_fn)
```

nn.Module 提供 Hook 机制，可以在不修改 forward 代码的情况下：
- `register_forward_hook`：前向传播后触发（监控输出）
- `register_forward_pre_hook`：前向传播前触发（监控输入）
- `register_backward_hook`：反向传播后触发（监控梯度）

典型用途：特征可视化、梯度裁剪、中间层输出提取。

#### 七、设备迁移

```python
net.to('cuda')    # 所有参数和缓冲区移到GPU
net.to('cpu')     # 移回CPU
```

`to()` 递归遍历所有子模块，将参数和缓冲区迁移到指定设备。没有 nn.Module 你需要手动对每个张量调用 `.to()`。

### 对比：用 nn.Module vs 不用 nn.Module

```python
# ============ 不用 nn.Module：手动实现 ============
class ManualNet:
    def __init__(self):
        self.w1 = torch.randn(2, 8, requires_grad=True)
        self.b1 = torch.randn(8, requires_grad=True)
        self.w2 = torch.randn(8, 8, requires_grad=True)
        self.b2 = torch.randn(8, requires_grad=True)
        self.w3 = torch.randn(8, 2, requires_grad=True)
        self.b3 = torch.randn(2, requires_grad=True)

    def forward(self, x):
        h1 = torch.relu(x @ self.w1 + self.b1)
        h2 = torch.relu(h1 @ self.w2 + self.b2)
        out = h2 @ self.w3 + self.b3
        return out

    def parameters(self):          # 手动收集
        return [self.w1, self.b1, self.w2, self.b2, self.w3, self.b3]

    def to(self, device):          # 手动迁移
        for p in self.parameters():
            p.data = p.data.to(device)

    def state_dict(self):          # 手动序列化
        return {'w1': self.w1, 'b1': self.b1, ...}

    def train(self): pass          # Dropout/BatchNorm？自己处理
    def eval(self): pass

# ============ 用 nn.Module：自动一切 ============
class ClassifyNetwork(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Linear(2, 8), nn.ReLU(),
            nn.Linear(8, 8), nn.ReLU()
        )
        self.classify = nn.Linear(8, 2)

    def forward(self, x):
        return self.classify(self.features(x))

# 参数管理、设备迁移、模式切换、序列化、Hook → 全部自动
```

**10层网络时差距更大：手动管理要维护20+个参数张量，nn.Module 只要往 Sequential 里 append。**

---

### nn.Module 的本质：深度学习框架的"骨架协议"

| 能力 | nn.Module 提供 | 如果没有 |
|------|---------------|---------|
| 参数注册 | `self.xxx = nn.Linear()` 自动注册 | 手动创建+手动收集 |
| 参数收集 | `net.parameters()` 一行搞定 | 手动维护列表 |
| 自动求导 | 前向自动建计算图 | 手动确保计算图连通 |
| 模式切换 | `train()`/`eval()` 递归传播 | 手动每层切换 |
| 设备迁移 | `to('cuda')` 一行搞定 | 手动逐张量迁移 |
| 序列化 | `state_dict()`/`load_state_dict()` | 手动收集/恢复 |
| 嵌套结构 | Sequential/ModuleList 自动管理 | 手动拼接 |
| Hook | 注册回调监控任意层 | 修改 forward 代码 |

### 一句话总结
> 继承 nn.Module 不是形式主义，而是接入 PyTorch 的"骨架协议"——它提供了参数自动注册、自动求导、模式切换、设备迁移、序列化、嵌套管理和 Hook 七大基础设施。不用它，这些全要手动实现，且容易出错。框架的价值就是让你只关注 `forward` 里的网络逻辑，其余全部自动化。
