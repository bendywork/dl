## 今日学习内容

- 知识点 1：交叉熵损失函数（`07_交叉熵损失函数演示.py`）
  - 信息论根源：信息量 I(p) = -log₂(p)，事件越罕见信息量越大；熵 H(P) 是信息量的期望
  - 交叉熵 H(P,Q) = -Σ P(x)·log(Q(x))，用分布 Q 编码时，数据实际来自 P 所产生的额外代价
  - 交叉熵 ≥ 熵，等号在 Q=P 时成立；最小化交叉熵等价于最小化 KL 散度
  - 二分类 BCE：L = -[y·log(ŷ) + (1-y)·log(1-ŷ)]；多分类 CCE：L = -log(ŷₖ)，只看真实类别概率
  - 交叉熵 vs MSE：MSE 对"自信且错误"惩罚不够，且与 sigmoid 组合会出现梯度消失；BCE 梯度 = ŷ - y，始终有效

- 知识点 2：分类网络工程实现（`08_ClassifyNetwork分类网络.py` + `09_Predictor预测器.py`）
  - `ClassifyNetwork`：features 提取层（Linear→ReLU→Linear→ReLU）+ classify 决策层
  - `training` 模式返回 logits（置信度），`eval` 模式返回 softmax 概率；通过 `self.training` 标志切换
  - `Predictor` 类：封装模型加载、预测、训练全流程；`@torch.no_grad()` 装饰器用于推理
  - 完整训练五步：前向 → loss → zero_grad → backward → step
  - `state_dict` 保存模型参数；加载时用 `load_state_dict()` 恢复

- 知识点 3：state_dict 与 named_parameters 对比（`15_PyTorch_state_dict与named_parameters对比.md`）
  - `named_parameters()`：只含可学习参数（Parameter），返回迭代器，和模型内部是同一对象（引用）
  - `state_dict()`：含可学习参数 + Buffer（如 BatchNorm 的 running_mean），返回 OrderedDict，是独立拷贝
  - 修改 `named_parameters()` 的值会直接影响模型；修改 `state_dict()` 的值不影响模型
  - 场景选择：保存/加载用 `state_dict()`；冻结层用 `named_parameters()`；传优化器用 `parameters()`

- 知识点 4：深度学习代码流程总结（`11_深度学习代码流程练习.py`）
  - 标准训练循环：数据加载 → 模型创建 → 损失函数 + 优化器 → epoch 循环 → batch 训练 → 评估
  - `net.train()` / `net.eval()` 切换影响 Dropout、BatchNorm 等模块的行为
  - `torch.no_grad()` 上下文：评估时关闭梯度计算，节省显存和计算
  - 推理时 `argmax(dim=1)` 将类别概率转换为预测类别 id

## 核心收获

1. 交叉熵之所以优于 MSE 用于分类，核心在于梯度：BCE 的梯度仅为 (ŷ - y)，不含 sigmoid 导数项，在预测极端错误时仍能产生有效梯度驱动修正
2. `training` 和 `eval` 模式不仅影响 Dropout/BN，也可以用 `self.training` 标志控制 forward 的返回内容（logits vs softmax），这是工程实践中的常见写法
3. `state_dict` 是拷贝，`named_parameters` 是引用——保存用前者，调参/冻结用后者，混淆会导致意料之外的 bug
4. 深度学习训练循环的本质就是：用小批次数据不断更新参数，每个 batch 的五步（前向、loss、清零梯度、反向、更新）是固定模式

## ⚠️ 易错点回顾

1. **"CrossEntropyLoss 输入要先过 softmax"** → 错。PyTorch 的 `nn.CrossEntropyLoss` 内部已包含 LogSoftmax，输入应为原始 logits；手动 softmax 后再传入会导致计算错误
2. **"state_dict 不含 BatchNorm 的 running_mean"** → 错。running_mean 是 buffer，不参与梯度但是模型状态的一部分，state_dict 必须包含它，否则 BN 加载后推理结果会出错
3. **"修改 state_dict 里的值能改变模型权重"** → 错。state_dict 是独立拷贝，必须调用 `model.load_state_dict(sd)` 才能将修改写回模型
4. **评估时忘记 `net.eval()` 和 `torch.no_grad()`** → BN 会继续更新统计量，Dropout 仍随机丢弃，导致评估结果不稳定且浪费计算
