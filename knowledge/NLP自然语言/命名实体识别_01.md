# 命名实体识别（NER）

## 📌 核心问题
> 如何从文本中自动识别出有业务价值的实体（人名、地名、机构名、时间等）？

## 🌱 根源与动机

NER 是 NLP 信息抽取的基础：搜索引擎、智能客服、知识图谱构建都依赖它。

**序列标注思路**：把 NER 转化为每个 token 的分类问题，用 BIO/BMESO 标注体系：
- `B-TYPE`：实体开始
- `I-TYPE`：实体中间/结尾
- `O`：非实体

## 📐 理论推导

### BIO 标注示例

```
文本：  姚  明  是  篮  球  运  动  员
标注：B-PER I-PER O  O  O  O  O  O
```

### 模型架构：BERT + BiLSTM + CRF

```
输入token → BERT特征提取 → BiLSTM增强局部特征 → CRF解码（约束合法标签序列）
```

CRF 的作用：建模标签之间的转移约束（如 `I-PER` 不能直接接 `B-LOC`）

### BERT 直接接 FC（不用 CRF）

```
输入token → BERT → FC → softmax → 每个token的类别
```

### 嵌套实体问题

BIO 无法处理嵌套，解决方案：
- **Span 分类**：枚举所有片段，判断是否是实体及类型（spert 采用此方案）
- **指针网络**：预测实体头尾指针

## 💡 关键理解

- BERT 以**字为单位**输入，自然适合中文 NER（不需要分词）
- **CRF 层必要性**：单纯 softmax 每个位置独立预测，会出现 `O B-X I-Y` 这种非法序列
- NER 的核心挑战：**嵌套实体**（"南京大学"里包含"南京"）和**低频实体**（未见过的命名词）

## ⚠️ 易错点与常见误解

1. **BIO 和 BMESO 的区别**：BMESO 多了 M（middle）和 S（single），对单字实体更友好
2. **NER 评估用 Entity-level F1**，不是 token-level accuracy（整个实体识别正确才算对）
3. **训练数据标注**中，`[CLS]` 和 `[SEP]` 的标签设为 `O` 或特殊标签，不参与 loss 计算
4. **BERT 有最大长度 512 限制**，长文本需要滑动窗口截断处理
