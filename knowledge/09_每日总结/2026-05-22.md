# 📅 2026-05-22 每日学习总结

## 今日学习内容

- 知识点 1：反向传播中 W 转置的由来（`05_BP中转置矩阵推导演示.py` + `13_反向传播中W转置的由来.md`）
  - 从标量链式法则出发，逐步推导出为何反向传播中出现 Wᵀ
  - x 的每个分量通过 W 的不同行（多条路径）影响 y 的多个分量，链式法则沿路径求和时，下标翻转 = 矩阵转置
  - 用非方阵案例（W 3×2）验证：Wᵀ 变成 2×3，维度才能匹配 ∂L/∂x 的形状
  - VJP（Vector-Jacobian Product）视角：反向传播本质是把上游梯度向量乘到 Jacobian 的"列"上，须转置

- 知识点 2：PyTorch Linear 层 W 形状为 (out, in) 的原因（`14_PyTorch的Linear层W形状详解.md`）
  - 数学惯例：y = W @ x，W 天然是 (out, in)，每一行对应一个输出神经元
  - PyTorch 用批量行向量 X(batch, in)，公式变为 Y = X @ Wᵀ + b，W 形状不变，只是放在右边须转置
  - 代码验证：`x @ linear.weight.T + linear.bias` 等价于 `linear(x)`
  - 前向的 Wᵀ 与反向传播的 Wᵀ 是同一个转置，贯穿始终

- 知识点 3：为什么需要激活函数（`06_为什么需要激活函数.py`）
  - 用 XOR 问题直观演示：线性网络无论堆多少层，等价于一层线性变换，无法分离非线性数据
  - 加入 Sigmoid 激活函数后，同样的网络结构成功收敛，损失几乎降到 0
  - 可视化对比：无激活函数只能画直线决策边界；有激活函数可以画曲线

## 核心收获

1. W 转置不是记号约定，是标量链式法则展开后，下标翻转的数学必然；用维度推导（n,) = ?(n,m) @ (m,)）可以直接"算"出转置
2. PyTorch 的 W 形状 (out, in) 和数学课本完全一致，反直觉的是它把输入放左边导致内部用 Wᵀ，理解这一点后前向和反向的 Wᵀ 就不再困惑
3. 激活函数的核心价值：打破线性叠加，让多层网络真正能表达非线性函数；没有激活函数堆层等于白堆
4. VJP 是深度学习反向传播的理论核心：梯度 = 上游向量 × Jacobian 转置，这是 Wᵀ 出现的最根本原因

## ⚠️ 易错点回顾

1. **"Wᵀ 是约定，不是推导出来的"** → 错。从 2×2 标量展开就能亲眼看到转置出现，是数学必然
2. **"PyTorch 的 W 形状是 (in, out)"** → 错。打印 `linear.weight.shape` 得到的是 (out_features, in_features)，和直觉相反但和数学一致
3. **"堆更多线性层可以逼近非线性函数"** → 错。多层线性层可以合并为一层，本质没有增加表达能力；必须加非线性激活函数
4. **混淆 JVP 和 VJP**：JVP = J·v，用于前向模式自动微分；VJP = Jᵀ·v，用于反向模式（深度学习标准）
