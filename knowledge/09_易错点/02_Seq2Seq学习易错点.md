> 记录学习 Seq2Seq 过程中踩过的坑、纠正过的误解。
> 创建日期：2026-06-10

## 易错点 1：❌ 以为 Seq2Seq 是"逐词对应翻译"

### 错误理解

"每个输入 token 经过 LSTM → Linear → Softmax，立刻输出一个对应的目标词"

```
"我" → LSTM → Linear → Softmax → "I"
"爱" → LSTM → Linear → Softmax → "love"
"中国" → LSTM → Linear → Softmax → "China"
```

### 正确理解

Seq2Seq 分两个独立阶段：

```
阶段一（编码器）：只读不输出
  "我" → LSTM → h₁ → "爱" → LSTM → h₂ → "中国" → LSTM → h₃
                                                            ↓
                                                      (h₃, c₃) 整句压缩

阶段二（解码器）：从压缩状态开始逐词生成
  (h₃, c₃) + <SOS> → "I"
  (h, c) + "I"      → "love"
  (h, c) + "love"   → "China"
  (h, c) + "China"  → <EOS> 停止
```

### 混淆的是什么

"逐词对应翻译"其实是**同步多对多（N→N 等长标注）**，用于词性标注、NER 等任务，不是 Seq2Seq。

## 易错点 2：❌ 不理解为什么逐词翻译不行

### 原因 1：词数不对

源语言和目标语言的词数经常不一样，无法一一对应。

```
英文 "I love you" (3词) → 法文 "Je t'aime" (2词)
逐词翻译：第3个输入词没有对应的输出位置 → 输出啥？

英文 "learning" (1词) → 中文 "机器学习" (4字)
逐词翻译：1个输入只给1个输出位置 → 剩下3个字放哪？
```

### 原因 2：词序不对

逐词翻译的输出顺序永远和输入一样，但目标语言的语序可能完全不同。

```
英文 "a red apple" → 法文 "une pomme rouge"

逐词翻译按英文顺序输出：
  "a" → "une"    ✅
  "red" → "rouge" ← 翻对了但位置错了
  "apple" → "pomme" ← 翻对了但位置错了

结果: "une rouge pomme" ❌ 法语语法错误！
正确: "une pomme rouge" ✅ 法语形容词放名词后面
```

### 原因 3：没有上下文

逐词翻译处理当前词时，看不到后面的词，无法根据上下文做判断。

```
"I went to the bank"  → bank = 银行
"I sat by the bank"   → bank = 河岸

逐词翻译处理 "bank" 时：不知道后面是 "went to" 还是 "sat by" → 猜错
Seq2Seq 处理 "bank" 时：编码器已读完整句，h 和 c 包含上下文 → 翻对
```

## 易错点 3：❌ 不理解 Linear(hidden_size, vocab_size) 为什么需要

### 错误理解

"为什么要把 256 维映射到 10000 维？这个维度怎么定下来的？"

### 正确理解

解码器每一步的核心任务：**从词表里选一个词**。

```
LSTM 输出 h: 256维的抽象向量（人看不懂的内部表示）
     ↓ Linear(256, vocab_size)
logits: vocab_size维（每个维度 = 词表里一个词的得分）
     ↓ softmax
probs: vocab_size维（每个维度 = 对应词的概率，加起来=1）
     ↓ argmax
pred: 1个整数（概率最大的词的ID）
```

**vocab_size 决定输出维度**：词表有多少个词，logits 就必须是多少维。

**hidden_size 是 LSTM 内部的"思考维度"**，和词表大小无关，两者通过 Linear 连接。

### W.T 的问题

PyTorch 的 `nn.Linear(256, 100)` 把权重存成 `(100, 256)` 而不是 `(256, 100)`，所以计算时要用 `h @ W.T`。这不是数学需要，只是 PyTorch 的 API 存储习惯。

```
h:    (batch, 256)
W:    (100, 256)     ← PyTorch 存反了
W.T:  (256, 100)     ← 转置回来才能做矩阵乘法
h @ W.T → (batch, 100)
```

## 易错点 4：❌ 混淆 sigmoid 和 softmax

### 错误

说成 "scaoid" 或 "sigmoid"，不确定用哪个。

### 正确

| 激活函数 | 用途 | 输出含义 |
|---------|------|---------|
| **sigmoid** | 二分类 | 单个值 ∈ (0,1)，是/否的概率 |
| **softmax** | 多分类 | 多个值加起来=1，每个类别的概率 |

Seq2Seq 解码器从词表（如100个词）里选一个词 → 100分类问题 → **用 softmax**。

## 易错点 5：❌ 混淆交叉熵损失函数和置信度

### 错误理解

"交叉熵损失函数得到每个类别的置信度"

### 正确理解

```
Softmax    → 得到置信度（概率分布）
交叉熵     → 拿置信度和真实标签比较，算出"差多少"（损失值）

这是两个不同的事：
  softmax: [0.02, 0.94, 0.01, ...]  ← 置信度
  交叉熵:  用上面的概率和真实标签算一个数 ← 损失（越小越好）
```

## 易错点 6：❌ 以为编码器的 (h, c) 是每步都"加"进解码器

### 错误理解

"每一步都要把编码器的两个向量加进去"

### 正确理解

编码器的 `(h, c)` 只在**开头**作为解码器 LSTM 的**初始状态**：

```
解码器初始: h₀ = context_h,  c₀ = context_c

第1步: 输入<SOS> → LSTM → 更新 h₁, c₁ → 选词
第2步: 输入上一步词 → LSTM(h₁, c₁) → 更新 h₂, c₂ → 选词
第3步: 输入上一步词 → LSTM(h₂, c₂) → 更新 h₃, c₃ → 选词
...

h 和 c 随着解码器自己跑而自然更新，不需要手动"加"进去
```

## 易错点 7：❌ 不清楚生成何时停止

### 两种停止方式

| 方式 | 说明 | 角色 |
|------|------|------|
| `<EOS>` token | 解码器输出结束符 → 停止 | 主要方式，模型自己学会何时停 |
| `max_len` | 生成到第 N 步强制停止 | 兜底保险，防止无限生成 |

实际代码两个都用：`for t in range(max_len)` 是兜底，`if pred == EOS: break` 是主要判断。
