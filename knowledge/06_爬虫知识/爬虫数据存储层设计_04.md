# 爬虫数据存储层设计

## 📌 核心问题
> 爬虫采集的海量数据如何高效、安全地存入 MySQL？如何设计数据模型保证一致性？连接池如何避免连接耗尽？

## 🌱 根源与动机

### 爬虫存储的三个核心挑战

1. **连接管理** — 爬虫是长时运行任务，MySQL 默认 8 小时断开空闲连接，爬虫等一晚上回来写库直接报错
2. **写入性能** — 逐条 INSERT 5000 条数据可能需要几十秒；批量写入 500 条一批只需几秒
3. **数据去重** — 同一只股票的同一日 K 线数据如果被重复采集，如何避免插入重复数据？

### 为什么选 Peewee 而不是 SQLAlchemy？

| 维度 | Peewee | SQLAlchemy |
|------|--------|-----------|
| 学习成本 | ⭐ 极低（直觉式 API） | ⭐⭐⭐⭐ 高（概念复杂） |
| 项目适配度 | ✅ 爬虫只需 CRUD + 建表 | ⚠️ 功能过剩 |
| 与 DBUtils 整合 | ✅ 自定义 PooledMySQLDatabase | ✅ 也有连接池方案 |
| 迁移支持 | ⚠️ 需第三方库 | ✅ Alembic 成熟 |
| 性能 | ✅ 轻量 ORM，开销小 | ✅ 功能更多，略重 |

## 💡 核心设计

### 1. BaseModel — 所有表的统一审计字段

```python
class ScxBaseModel(Model):
    """所有 Model 的公共基类"""
    class Meta:
        database = db
        table_prefix = "scx_"  # 业务前缀

    id = AutoField()                              # 自增主键
    created_at = DateTimeField(default=datetime.now)  # 创建时间
    updated_at = DateTimeField(default=datetime.now)  # 更新时间
    source = CharField(max_length=32, default="eastmoney")  # 数据来源
    fetched_at = DateTimeField(default=datetime.now)  # 采集时间

    def save(self, *args, **kwargs):
        self.updated_at = datetime.datetime.now()  # 每次保存自动更新
        return super().save(*args, **kwargs)
```

**设计要点：**
- `source`：标记数据从哪来（东方财富/巨潮资讯/消防法规），方便溯源
- `fetched_at`：记录采集时间而非数据产生时间，排查数据延迟问题时至关重要
- `updated_at` 自动更新：重写 `save()` 方法，每次保存自动刷新

### 2. 连接池 — DBUtils + Peewee 桥接 ⭐

这是项目中最精巧的部分。Peewee 默认每次查询创建新连接，爬虫场景会耗尽连接。

```python
class PooledMySQLDatabase(MySQLDatabase):
    """DBUtils 连接池 + Peewee ORM 桥接"""
    
    def __init__(self):
        self._pool = None
        super().__init__(database=settings.mysql_database)
    
    def _ensure_pool(self):
        if self._pool is not None:
            return
        self._pool = PooledDB(
            creator=pymysql,              # 连接创建函数
            maxconnections=10,            # 最大连接数
            mincached=3,                  # 最少空闲连接
            maxusage=1000,                # 单连接复用1000次后回收
            blocking=True,                # 连接池满时等待而不是报错
            host=settings.mysql_host,
            port=settings.mysql_port,
            user=settings.mysql_user,
            password=settings.mysql_password,
            database=settings.mysql_database,
            charset="utf8mb4",            # 支持 emoji 和特殊字符
        )
    
    def _connect(self):
        self._ensure_pool()
        conn = self._pool.connection()  # 从池中取连接，不新建
        return conn
```

**关键参数解释：**

| 参数 | 值 | 为什么 |
|------|-----|--------|
| `maxconnections` | 10 | 爬虫并发 10，每个 worker 占用一个连接，刚好够用 |
| `mincached` | 3 | 空闲时保持 3 个连接，避免冷启动时等待连接建立 |
| `maxusage` | 1000 | 单连接复用 1000 次后回收，防止连接老化导致的数据异常 |
| `blocking` | True | 连接池满时等待，而不是抛异常导致爬虫中断 |
| `charset` | utf8mb4 | 股吧帖子中包含 emoji（如 📈📉），utf8 存不下 |

### 3. 联合唯一索引 — 避免重复数据

每个表都设计了联合唯一索引，保证 INSERT 时自动去重：

```python
class StockKlineDaily(ScxBaseModel):
    class Meta:
        table_name = "scx_stock_kline_daily"
        indexes = (
            (("symbol", "trade_date", "period", "adjust"), True),  # True = 唯一索引
        )
    
    symbol = CharField(max_length=6)      # 如 "600519"
    trade_date = DateField()              # 如 2026-06-12
    period = CharField(max_length=8)      # daily/weekly/monthly
    adjust = CharField(max_length=3)      # qfq/hfq/""
    open = DecimalField(...)
    # ...
```

**这意味着：** 同一只股票 + 同一天 + 同一周期 + 同一复权方式 → 只能有一条记录。

### 4. Upsert 策略 — INSERT ON DUPLICATE KEY UPDATE

爬虫经常需要"增量更新"：新数据插入，已有数据更新。项目的解决方案是原生 SQL：

```python
def _raw_upsert(self, model, row: dict, conflict_keys: list[str], update_keys: list[str]):
    """原生 SQL upsert：INSERT ... ON DUPLICATE KEY UPDATE"""
    table = model._meta.table_name
    cols = list(row.keys())
    placeholders = ", ".join(["%s"] * len(cols))
    col_names = ", ".join(f"`{c}`" for c in cols)
    update_clause = ", ".join(f"`{k}` = VALUES(`{k}`)" for k in update_keys)
    
    sql = f"INSERT INTO `{table}` ({col_names}) VALUES ({placeholders}) 
           ON DUPLICATE KEY UPDATE {update_clause}"
    
    conn = db.connection()
    cursor = conn.cursor()
    try:
        cursor.execute(sql, values)
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        cursor.close()  # ⚠️ 关键！必须手动关闭游标
```

**为什么不用 Peewee 的 `on_conflict` ？**
- Peewee 的 `on_conflict` 在 MySQL 上有兼容性问题
- 原生 SQL 更可控，性能也更好
- 配合连接池释放连接更精确

**⚠️ 关键易错点：游标必须关闭！**
`cursor.close()` 如果不调用，连接池中的连接会因未释放游标而泄漏，最终耗尽所有连接。

### 5. 批量写入管道

```python
class StoragePipeline:
    def __init__(self, batch_size: int = 500):
        self.batch_size = batch_size
        self._buffer: list[dict] = []
    
    async def process_item(self, item: dict):
        self._buffer.append(item)
        if len(self._buffer) >= self.batch_size:
            await self.flush()  # 满 500 条 → 写入数据库
    
    async def flush(self):
        if not self._buffer:
            return
        saved = 0
        for item in self._buffer:
            try:
                Article.create(**item)
                saved += 1
            except IntegrityError:
                Article.update(**item).where(Article.url == item["url"]).execute()
        self._buffer.clear()
```

## 📊 数据模型设计原则

从项目实践中总结的设计原则：

1. **一个 API 接口 → 一个 Model** — 不要把一个接口的返回字段拆成多个表
2. **字段名用英文，注释写中文** — 代码中 `change_pct`（涨跌幅），数据库列名也英文
3. **金额用 DECIMAL，不要用 FLOAT** — 精度问题（0.1 + 0.2 ≠ 0.3 在 FLOAT 中）
4. **成交量用 BigIntegerField** — A股每天成交量可达数十亿手，Integer 不够
5. **时间字段：日期用 DateField，时间用 DateTimeField** — 不要混用
6. **业务前缀** — 所有表名以 `scx_` 开头（来自项目 CLAUDE.md 规范）

## ⚠️ 易错点与常见误解

1. **永不关闭游标** → 连接泄漏，最终 `maxconnections` 耗尽，所有请求阻塞
2. **用 FLOAT 存金额** → 0.1 + 0.2 = 0.30000000000000004，金融数据绝不允许
3. **不设唯一索引** → 爬虫重跑产生大量重复数据，清理成本极高
4. **逐条 INSERT 不批量** → 5000 条数据 500 次数据库往返 vs 10 次，性能差 50 倍
5. **`blocking=False`** → 连接池满时抛异常导致爬虫中断，应该设为 True 排队等待
6. **字符集用 utf8** → MySQL 的 utf8 不是真正的 UTF-8（只有 3 字节），emoji 存不进去
