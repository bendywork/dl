## 📐 完整技术选型清单

### 第一层：核心框架

| 组件 | 选型 | 版本 | 职责 |
|------|------|------|------|
| **爬虫框架** | `crawlee` | ≥1.0 | 请求调度、路由分发、并发控制、去重 |
| **HTTP 客户端** | `httpx` | ≥0.28 | 异步 HTTP 请求（Crawlee 内置） |
| **浏览器引擎** | `playwright` | ≥1.50 | JS 渲染与反爬页面交互 |

**选型理由：** Crawlee 是 2026 年增长最快的 Python 爬虫框架，原生 async/await，内置 Playwright 集成和反爬能力。

### 第二层：解析与清洗

| 组件 | 选型 | 版本 | 职责 |
|------|------|------|------|
| **HTML 解析** | `parsel` | ≥1.9 | CSS/XPath 选择器提取字段 |
| **快速解析** | `selectolax` | ≥0.3 | Modest 引擎极速解析（大文本备选） |
| **HTML 清洗** | `BeautifulSoup` | (lxml) | HTML → 纯文本转换 |

**选型理由：** parsel 是 Scrapy 同款解析器，CSS + XPath 双支持，语法直觉。selectolax 作为大文本场景的性能备选。

### 第三层：数据存储

| 组件 | 选型 | 版本 | 职责 |
|------|------|------|------|
| **ORM** | `peewee` | ≥3.17 | 模型定义、CRUD 操作、建表迁移 |
| **连接池** | `DBUtils` | ≥3.1 | MySQL 连接复用，防止连接耗尽 |
| **数据库驱动** | `pymysql` | ≥1.1 | MySQL 原生协议驱动 |

**选型理由：** Peewee 是 Python 最轻量的 ORM，API 直觉友好。DBUtils 解决 Peewee 默认无连接池的问题。比 SQLAlchemy 学习成本低得多。

### 第四层：工程化

| 组件 | 选型 | 版本 | 职责 |
|------|------|------|------|
| **配置管理** | `pydantic-settings` | ≥2.0 | 类型安全的环境变量加载 |
| **日志** | `loguru` | ≥0.7 | 结构化日志 + 自动轮转 |
| **任务调度** | `apscheduler` | ≥3.10 | 定时/周期采集任务 |
| **重试机制** | `tenacity` | ≥8.0 | 请求失败自动重试与退避 |
| **数据分析** | `pandas` | ≥3.0.3 | DataFrame 处理 API 返回的表格数据 |

### 第五层：开发工具

| 组件 | 选型 | 版本 | 用途 |
|------|------|------|------|
| **包管理** | `uv` / `pip` | — | 依赖安装（项目使用 uv.lock） |
| **测试** | `pytest` + `pytest-asyncio` | ≥8.0 | 单元测试与异步测试 |
| **Python** | `Python` | ≥3.11 | 语言运行时 |

## 💡 为什么不选 Scrapy？（完整对比）

项目 PRD 中的技术选型决策：

| 拒绝理由 | 详细说明 |
|---------|---------|
| **Twisted 架构过时** | 非标准 async/await，与 httpx 等现代异步库不兼容 |
| **项目结构太重** | 固定 CLI 约定（`scrapy startproject`），灵活性低 |
| **学习成本高** | Settings + Signals + Middleware + Pipeline 体系复杂 |
| **DBUtils 集成不便** | Scrapy 有自己的连接管理，注入 DBUtils 需绕过框架 |

## 🛠️ 数据采集架构策略

### 为什么用远程 AKShare 服务而不是本地安装？

项目使用远程 API 服务（`http://remote_server:8900/api`）：
- **优点：** 不需要本地维护 AKShare 版本、统一管理 IP 和反爬策略
- **通信：** POST JSON 请求 + Bearer Token 鉴权
- **降级：** 如果远程服务不可用，可以本地安装 AKShare 作为降级方案

### 为什么股吧用 Playwright 而不用 API？

- 东方财富股吧没有公开 API
- 页面内容是 JavaScript 动态渲染的
- 评论是 AJAX 延迟加载的，需要等待元素出现

## ⚠️ 易错点与常见误解

1. **技术选型不考虑维护成本** → 选 Scrapy 看社区大，但团队只有 asyncio 经验，学习 Twisted 成本远超框架价值
2. **把 AKShare 当万能数据源** → 它只是东方财富的封装，不同数据源字段名、单位可能不同
3. **一个项目只用一种爬取方式** → 本项目用 API + 浏览器 + HTTP 三种方式，因为不同数据源需要不同手段
4. **过度设计** → 不是所有场景都需要分布式，5000 只股票的单机定时采集，Crawlee + APScheduler 足够
