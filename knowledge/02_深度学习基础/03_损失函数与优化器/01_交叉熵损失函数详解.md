# 交叉熵损失函数详解

## 📌 核心问题
> 分类任务为什么用交叉熵而不是 MSE？交叉熵到底是什么？

## 🌱 根源与动机：从信息论说起

### 信息量

事件越罕见，包含的信息量越大：

```
I(p) = -log₂(p)

p=1.0  → 0 bits    （必然事件，毫无信息）
p=0.5  → 1 bit     （抛硬币，1 bit 信息）
p=0.01 → 6.64 bits （罕见事件，大量信息）
```

### 熵 H(P)：一个分布的"平均不确定性"

```
H(P) = -Σ P(x) · log₂(P(x))

公平硬币 [0.5, 0.5]  → H = 1.00 bits  （最大不确定性）
偏向硬币 [0.9, 0.1]  → H = 0.47 bits  （不确定性降低）
必定硬币 [1.0, 0.0]  → H = 0.00 bits  （完全确定）
```

分布越均匀，熵越大；分布越集中，熵越小。

### 交叉熵 H(P,Q)：用 Q 编码 P 的代价

```
H(P, Q) = -Σ P(x) · log₂(Q(x))
```

用"错误分布 Q"去编码"真实分布 P"的数据，平均需要多少信息量。

- Q = P 时：H(P,Q) = H(P)，最低（完美预测）
- Q 离 P 越远：H(P,Q) 越大（预测越差）
- **交叉熵 ≥ 熵**，等号在 Q = P 时成立

### KL 散度：交叉熵 - 熵 = 额外代价

```
KL(P||Q) = H(P,Q) - H(P)
```

**优化交叉熵 = 最小化 KL 散度 = 让模型预测 Q 逼近真实分布 P**。这就是分类任务用交叉熵的根本原因。

## 📐 理论推导

### 二分类交叉熵（BCE）

```
L = -[y · log(ŷ) + (1-y) · log(1-ŷ)]

y  = 真实标签 (0 或 1)
ŷ  = 模型预测概率 (0~1)

y=1 时: L = -log(ŷ)        ŷ→1 则 L→0 ✓
y=0 时: L = -log(1-ŷ)      ŷ→0 则 L→0 ✓
```

### 多分类交叉熵（CCE）

```
L = -Σᵢ yᵢ · log(ŷᵢ)

y = one-hot 真实标签
ŷ = softmax 输出的概率分布

因为 y 是 one-hot，只有 yₖ=1：
L = -log(ŷₖ)   ← 只看真实类别上的预测概率
```

3 分类案例（猫/狗/鸟，真实=猫）：
- 自信正确 ŷ=[0.9, 0.05, 0.05] → L = 0.11
- 勉强正确 ŷ=[0.4, 0.3, 0.3]   → L = 0.92
- 完全错误 ŷ=[0.1, 0.1, 0.8]   → L = 2.30

## 💡 关键理解：为什么分类用交叉熵不用 MSE

### 原因1：梯度消失

```
sigmoid + MSE:   ∂L/∂z = (ŷ - y) × ŷ(1-ŷ)   ← ŷ≈0或1时 ŷ(1-ŷ)≈0，梯度消失！
sigmoid + BCE:   ∂L/∂z = ŷ - y               ← 没有 ŷ(1-ŷ) 项，梯度始终有效！
```

ŷ=0.01, y=1 时：MSE 梯度 = -0.0099（几乎不动），BCE 梯度 = -0.99（强力纠正）。

BCE 和 sigmoid 配合时，log 抵消了 sigmoid 导数中的 ŷ(1-ŷ)，这是数学上的精妙设计。

### 原因2：惩罚力度

```
MSE:  L = (ŷ-y)²    → 二次增长，最大才 1.0
BCE:  L = -log(ŷ)   → 对数增长，趋向 ∞
```

ŷ=0.001, y=1 时：MSE = 0.001（轻描淡写），BCE = 6.9（严厉惩罚）。

**交叉熵对"自信且错误"零容忍，MSE 则过于温和。**

## 🔧 代码实现

详见：`stage02/cross_entropy_demo.py`

PyTorch 用法：

```python
# 二分类
loss_fn = nn.BCELoss()           # 输入: ŷ 和 y 都是 (batch,)
loss_fn = nn.BCEWithLogitsLoss() # 输入: logits（内含 sigmoid），更稳定

# 多分类
loss_fn = nn.CrossEntropyLoss()  # 输入: logits(batch,C) + 标签(batch,)
                                 # 内含 LogSoftmax + NLLLoss
```

**注意**：PyTorch 的 `CrossEntropyLoss` 直接传 logits，不需要手动 softmax。

## ⚠️ 易错点与常见误解

1. **"交叉熵就是 -log(p)"** → 不完整。交叉熵是 -ΣP(x)logQ(x)，-log(p) 只是 one-hot 情况的简化形式
2. **"交叉熵和负对数似然是同一回事"** → 对。在分类任务中两者等价，但概念来源不同（信息论 vs 统计学）
3. **BCELoss 传入的预测值必须在 (0,1)"** → 对。如果传 logits 会 NaN。用 BCEWithLogitsLoss 更安全
4. **"CrossEntropyLoss 需要先 softmax"** → 错。PyTorch 的 CrossEntropyLoss 内部自带 LogSoftmax，传 logits 就行
5. **"交叉熵只能用于分类"** → 不对。任何需要让一个分布逼近另一个分布的场景都适用（如蒸馏、生成模型）
