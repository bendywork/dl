# LSTM 门为什么使用 Sigmoid 激活函数

## 📌 核心问题
> LSTM 的遗忘门、输入门、输出门为什么必须用 Sigmoid？为什么不用 tanh 或 ReLU？

## 🌱 背景：门的本质是什么

LSTM 细胞状态更新公式：

```
c_t = f_t * c_t-1 + i_t * g_t
```

其中 `f_t` 是遗忘门，它的语义是：

> "上一步积累的记忆，我要保留多少比例？"

这是一个**比例/权重**，不是一个"值"。
它的作用是对 `c_t-1` 做缩放，控制信息流量，所以必须是 **(0, 1)** 范围内的数。

## 📐 三种激活函数对比

### ✅ Sigmoid：正确选择

- 输出范围：**(0, 1)**
- `f_t = 1.0` → 完全保留记忆
- `f_t = 0.0` → 完全遗忘
- `f_t = 0.6` → 保留 60%

语义清晰，是天然的"阀门"。

### ❌ tanh：符号翻转问题

- 输出范围：**(-1, 1)**

```python
# 假设 f_t = -0.5（tanh 可能输出负值）
c_t = -0.5 * c_t_prev + ...
# 记忆的符号被翻转了！"遗忘-50%的记忆"没有物理意义
```

负值会让细胞状态符号随机翻转，破坏长期记忆的语义，训练也会变得不稳定。

### ❌ ReLU：梯度爆炸问题

- 输出范围：**[0, +∞)**

```python
# 假设 f_t = 5.0（ReLU 输出无上界）
c_t = 5.0 * c_t_prev + ...
# 记忆被放大5倍！每步都乘 >1 的系数
```

若每个时间步 `f_t > 1`，细胞状态会指数级增长，梯度随之爆炸，网络无法收敛。

## 🔑 g_t 为什么用 tanh？

注意区分：`g_t`（候选记忆）用的是 tanh，不是 Sigmoid。

```python
g_t = torch.tanh(x_t @ g_x_weight + h_t @ g_h_weight + g_h_bias)
```

- `g_t` 是"新信息的内容"，需要有正负方向，表达增强或抑制
- tanh 输出 (-1, 1)，正好表达"正向/负向记忆"
- 而 `i_t`（输入门）决定"要写入多少"，才是 Sigmoid

**规律：门（控制流量）用 Sigmoid，内容（信息本身）用 tanh。**

## 🔗 在 Seq2Seq 中的作用

编码器 LSTM 跑完所有时间步后：

```python
context_h = h_t  # 短期语义摘要
context_c = c_t  # 长期记忆摘要
```

正是因为门用了 Sigmoid，细胞状态 `c_t` 才能稳定地跨越多个时间步积累信息，不爆炸也不消失。最终这两个向量传给解码器作为初始状态，解码器才能从"读完源句子的脑子状态"出发逐词生成目标序列。

## 📋 一句话总结

| 组件 | 激活函数 | 原因 |
|------|---------|------|
| 遗忘门 f_t | Sigmoid | 比例系数，必须 (0,1) |
| 输入门 i_t | Sigmoid | 比例系数，必须 (0,1) |
| 候选记忆 g_t | tanh | 信息内容，需要正负方向 |
| 输出门 o_t | Sigmoid | 比例系数，必须 (0,1) |
| 隐状态 h_t | tanh(c_t) | 归一化输出，保持稳定范围 |

> 本质：**凡是做乘法控制流量的地方，用 Sigmoid；凡是表达信息内容的地方，用 tanh。**
