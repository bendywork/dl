# 为什么需要RNN及其根本局限

## 📌 核心问题
> 普通神经网络无法处理序列信息，RNN试图解决但仍有根本局限——它实际上仍然偏局部。

## 🌱 根源与动机

### 什么是时间步（Time Step）

RNN里的"时间步"就是把语言的先后顺序当作时间流逝来建模。一句话说出来，词有先后——"我"先说，"喜欢"后说，"深度学习"最后说。RNN把这个顺序映射成时间轴：第1个词是t=1，第2个词是t=2，依次递推。所以叫"时间步"。

用"时间"而不只是"顺序"，是因为RNN的处理过程本身就是递进的——必须先算h₁才能算h₂，必须先算h₂才能算h₃，像时间一样不可逆、不可并行。这跟Transformer不一样，Transformer所有token是同时处理的，所以Transformer里就不叫"时间步"。

**一句话：时间步 = 把语言的前后顺序当作时间流逝来建模，既是语义的先后，也是计算的前后依赖。**

### 普通全连接网络的问题

不是"只能记住局部信息"，而是**根本就没有序列的概念**。处理"我喜欢深度学习"时：

```
我   → [Wx+b] → 输出
喜欢 → [W+b] → 输出    ← 每个token独立处理，互相完全不知道
深度 → [Wx+b] → 输出
学习 → [Wx+b] → 输出
```

每个token用的是同一组W和b，但它们之间没有任何信息交流。"我"的输出和"喜欢"的输出没有任何联系——网络根本不知道"我"和"喜欢"出现在同一句话里。

### RNN 要解决的核心问题

让每个token在处理时，能"看到"之前所有token的信息。机制是递归：

```
h₁ = tanh(W·x₁ + b)                        ← 只有"我"的信息
h₂ = tanh(W·x₂ + U·h₁ + b)                 ← "喜欢" + "我"的信息（通过h₁传递）
h₃ = tanh(W·x₃ + U·h₂ + b)                 ← "深度" + "喜欢"+"我"的信息（通过h₂）
h₄ = tanh(W·x₄ + U·h₃ + b)                 ← "学习" + "深度"+"喜欢"+"我"的信息
```

**关键**：h₄不是只包含h₃的信息，h₃里已经折叠了h₂，h₂里已经折叠了h₁。所以h₄理论上包含了整句话从头到尾的所有信息，只是被压缩在一个向量里。

## 📐 RNN仍然偏局部的根本原因：梯度消失

理论上是全局的，实际上确实偏局部的。

反向传播时梯度传递路径：

```
要更新W，梯度要从h₄一路传回h₁：
  ∂L/∂W → h₄ → h₃ → h₂ → h₁
```

每次经过tanh，梯度都要乘以tanh的导数（最大0.25），再乘以U。4步之后：

```
梯度 ≈ (tanh' × U)^4 × 原始梯度
```

如果 |tanh' × U| < 1，梯度**指数衰减**，传到h₁时几乎为零——这就是**梯度消失**。h₄"理论上"包含h₁的信息，但训练时梯度根本传不回去，所以h₁对h₄的**实际影响微乎其微**。

### 结论

RNN表面上处理了全序列，但长距离依赖它真的处理不好，实际上还是偏局部的。这也是为什么后来有了：
- **LSTM**：加门控缓解梯度消失
- **Transformer**：直接attention跳过递归，真正全局连接

## 💡 关键理解

用一句话概括：**RNN的递归结构让h_t理论上折叠了之前所有token的信息，但梯度消失导致长距离信息实际传不动——所以它确实还是偏局部的，只是比全连接网络好。**

类比：RNN像一个人读长文章，理论上读到最后记住了前面所有内容，但实际上只记得最近几段，远处的已经模糊了。

## 🔧 跨句子的问题

RNN基本不连跨句子。每句话是一个独立样本，h₀通常初始化为0。如果一定要连，可以把上一句的h_final作为下一句的h₀，但实践中很少这么做，因为：

1. 句子之间通常是独立样本（batch里是不同数据）
2. 梯度消失问题跨句更严重
3. 真正的跨句上下文理解，是Transformer和后面的大模型解决的问题

## ⚠️ 易错点与常见误解

1. **误解：RNN已经解决了序列问题** → 没有完全解决，长距离依赖仍是瓶颈
2. **误解：RNN的hidden state真的包含了全部历史信息** → 理论上是的，实际训练中远距离信息几乎丢失
3. **误解：RNN可以跨句子传递上下文** → 实践中基本不做，是Transformer的领域
