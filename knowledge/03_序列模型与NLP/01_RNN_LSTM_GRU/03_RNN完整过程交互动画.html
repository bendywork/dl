全连接的局限 — 逐 token 独立变换
理解 FC 的运算本质，才能感受 RNN 补上了什么
FC 对序列的处理方式：逐 token 独立变换，每个时刻 xi 只经过 W 矩阵变换， 不知道其他 token 存在。这等价于：

h_i = X_i · U + b   其中 U 对每个 token 完全一样（参数共享），但输入只有当前 token 自己。
tt_with_fc() — 手动拆解全连接逐步运算 
bs, t, e = 1, 5, 128
linear = nn.Linear(e, e * 2)        # [128 → 256]
token_embs = torch.randn(bs, t, e)  # [1, 5, 128]

# ── 向量化写法 ──
token_new_embs = linear(token_embs)  # [1,5,128] → [1,5,256]

# ── 等价的手动循环拆解 ──
token_new_embs2 = []
for i in range(t):
    xi = token_embs[:, i, :]             # [bs, e]
    hi = xi @ linear.weight.T + linear.bias  # [bs,e]×[e,2e] → [bs,2e]
    token_new_embs2.append(hi[:, None])  # [bs, 1, 2e]

# ⚠️  每个时刻的 hi 完全独立，没有信息流动
FC 的信息流向示意
核心问题："从这里怎么回家" — FC 在处理"回家"时， 完全不知道前面有"从这里"，也不知道"怎么"这个疑问词的存在。 每个 token 的新特征只由自己决定。
RNN 核心公式拆解
H_t = act(U · X_t + W · H_{t-1})
Ht = act( U · Xt + W · Ht-1 )
各符号含义
H_t 当前时刻 t 的隐状态（hidden state），同时也是输出 → shape [bs, hidden_size]
X_t 当前时刻的输入 → shape [bs, input_size]（即 token_embs[:, i, :]）
H_{t-1} 上一时刻的隐状态，初始为全零向量 → shape [bs, hidden_size]
U 输入权重矩阵 weight_ih（input→hidden）→ shape [hidden, input]
W 循环权重矩阵 weight_hh（hidden→hidden）→ shape [hidden, hidden]
act 激活函数，PyTorch RNN API 默认 tanh，代码中也用了 ReLU
tt_with_rnn01() — 手动拆解 RNN 单步计算 
xh_linear = nn.Linear(e, e*2)   # U 矩阵  [128 → 256]
hh_linear = nn.Linear(2*e, e*2) # W 矩阵  [256 → 256]

uw, ub = xh_linear.weight.T, xh_linear.bias  # U [e, 2e]
ww, wb = hh_linear.weight.T, hh_linear.bias  # W [2e, 2e]

hi = torch.zeros((bs, 2*e))  # H_0 = 全零

for i in range(t):
    xi  = token_embs[:, i, :]         # X_t   [bs, e]
    xhi = xi @ uw + ub                 # U·X_t [bs, 2e]
    hhi = hi @ ww + wb                 # W·H_{t-1} [bs, 2e]
    hi  = F.relu(xhi + hhi)            # H_t = act(U·X_t + W·H_{t-1})
    token_new_embs.append(hi[:, None])

# ✅ 每一步 hi 都带着所有历史信息！
与 FC 的关键差异只有一行：hhi = hi @ ww + wb
这个 W·H_{t-1} 就是"记忆项"——它让当前时刻能看到之前所有时刻的信息。 U 和 W 在所有时刻共享同一套参数，这正是 RNN 的精髓。

每个时刻 t，Cell 接收 X_t（当前 token 向量）和 H_{t-1}（上一时刻隐状态）， 输出 H_t 并传递给下一时刻。
双向 RNN — Bidirectional
前向 + 反向，让每个位置都能看到全局上下文
单向 RNN 中，位置 t 只能看到 t 及之前 的信息。 双向 RNN 增加一个从右到左的 RNN，让每个位置同时感知 左右两侧 的上下文， 两者输出在最后一维拼接 concat([forward, backward], dim=-1)。
双向 RNN 信息流
tt_with_rnn02() — 双向 RNN 手动拆解 
# ── 前向：i = 0,1,2,3 ──
hi = torch.zeros((bs, 2*e))
for i in range(t):
    xi = token_embs[:, i, :]
    hi = F.relu(xi @ xh_linear1.weight.T + xh_linear1.bias +
                hi @ hh_linear1.weight.T + hh_linear1.bias)
    token_new_embs.append(hi[:, None])

# ── 反向：i = 3,2,1,0 ──
hi = torch.zeros((bs, 2*e))
for i in range(t - 1, -1, -1):
    xi = token_embs[:, i, :]
    hi = F.relu(xi @ xh_linear2.weight.T + xh_linear2.bias +
                hi @ hh_linear2.weight.T + hh_linear2.bias)
    token_new_embs2.append(hi[:, None])

# ── 拼接 ──
token_new_embs = torch.concat([token_new_embs, token_new_embs2], dim=-1)
# shape: [bs, t, 4e]  →  每个位置都"看到了"完整上下文
注意：反向 RNN 也是从零状态出发，只不过迭代方向相反—— 从序列末尾 t=3 向前扫到 t=0。最终两组输出在 dim=-1 维度拼接， 隐藏维度从 2e 变成 4e。
PyTorch nn.RNN API 对照验证
手动拆解与官方 API 输出完全一致 — tt_with_rnn04()
代码 tt_with_rnn04() 做了一件关键事：用同一组权重， 分别跑 nn.RNN 官方 API 和 手动循环拆解， 验证最大误差 ≈ 0（float32 精度内）。
tt_with_rnn03() — nn.RNN 完整参数说明 
rnn = nn.RNN(
    input_size=e,        # 每个时刻输入向量维度 [e]
    hidden_size=2*e,     # 隐状态/输出向量维度 [2e]
    num_layers=3,        # 堆叠几层 RNN
    nonlinearity='tanh', # 激活函数：tanh 或 relu
    bias=True,           # 是否有 bias 项
    batch_first=True,    # True → input shape [bs,t,e]
    dropout=0.0,
    bidirectional=True,  # 是否双向
)

rnn_output, rnn_state = rnn(token_embs)
# rnn_output: [bs, t, hidden*(2 if bidir)]  每个时刻的最后一层输出
# rnn_state:  [(2 if bidir)*num_layers, bs, hidden]  最后时刻状态
参数名称对照表（weight_ih / weight_hh）
参数名 含义 shape（单向，单层） 对应手动代码
weight_ih_l0 U 矩阵（input→hidden） [hidden, input] xh_linear.weight
bias_ih_l0 U 的偏置 [hidden] xh_linear.bias
weight_hh_l0 W 矩阵（hidden→hidden） [hidden, hidden] hh_linear.weight
bias_hh_l0 W 的偏置 [hidden] hh_linear.bias
tt_with_rnn04() — 对照验证核心片段 
# 从 API 中取出权重，复用于手动循环
uw, ub = rnn.weight_ih_l0.T, rnn.bias_ih_l0   # U [e,2e]
ww, wb = rnn.weight_hh_l0.T, rnn.bias_hh_l0   # W [2e,2e]

hi = torch.zeros((bs, 2*e))
for i in range(t):
    xi = token_embs[:, i, :]
    hi = F.tanh(xi @ uw + ub + hi @ ww + wb)
    token_new_embs.append(hi[:, None])

# 验证：应为接近 0 的极小值
print(torch.max(torch.abs(token_new_embs - rnn_output)))
# → tensor(2.3842e-07) ✅  完全一致
长时依赖问题 — RNN 的核心缺陷
tt_with_rnn05() 演示了梯度如何随序列长度指数衰减
RNN 每步做的是 H_t = tanh(U·X_t + W·H_{t-1})， 梯度反向传播时需要经过 tanh 的导数（≤1）× W 反复相乘， 序列越长，早期 token 对梯度的贡献越趋近于 0 — 这就是梯度消失。
tt_with_rnn05() — 长时依赖实验 
# 构造 10 个完全相同的 token（除第一个），观察输出差异
token_embs = torch.rand(1, 10, e)
token_embs = torch.tile(token_embs, dims=(2, 1, 1))  # 复制成 2 个 batch
token_embs[0, 0] = torch.rand(e)               # 只有第 0 个 batch 的第 1 个 token 不同

output, h_n = rnn(token_embs)

print(f"最后一个时刻输出:\n{output[:, -1, :]}")
print(f"第一个时刻输出:\n{output[:,  0, :]}")
# 问：两个 batch 在最后时刻的输出差异有多大？→ 接近相同
# 说明：第1个 token 的信息经过 10 步传播后几乎消失了

关键总结：RNN 通过"携带隐状态 H_t"解决了 FC 的信息隔离问题， 但隐状态本身会随时间衰减。LSTM 和 GRU 用门控机制缓解这一问题， 而 Transformer 用 Self-Attention 从根本上绕过了顺序传递。
