# 模型训练的数据划分：训练集 / 验证集 / 测试集

## 📌 核心问题
> 为什么模型训练需要划分三个数据集？只用训练集和测试集不够吗？

## 🌱 根源与动机

模型训练的目标是**泛化**——在没见过的数据上也能表现好。如果模型只在训练数据上表现好，到新数据就拉胯，那就是过拟合。

为了判断模型是否真正学到了规律（而不是死记硬背），我们需要**模型从未学习过的数据**来评估。

## 📐 三集划分

| 数据集 | 作用 | 什么时候用 | 类比 |
|--------|------|-----------|------|
| **训练集** | 模型学习用，更新参数 | 每个epoch都在用 | 课本习题 → 学知识 |
| **验证集** | 训练过程中调参、做决策 | 每个epoch结束后评估 | 模拟考试 → 检查学习效果 |
| **测试集** | 最终客观评估 | 训练全部结束后，只用一次 | 正式考试 → 真实水平 |

### 为什么需要验证集？

训练过程中每个 epoch 结束后要看"效果有没有变好"：

- F1 提升了 → 保存最佳模型
- F1 连续 N 轮没提升 → Early Stopping，停止训练
- 尝试不同的学习率、dropout → 选效果最好的配置

**这些决策都是用验证集做的。**

如果用测试集来做决策 → 调来调去其实是在迎合测试集 → 测试集的结果不再客观 → 无法判断模型的真实水平。

### 为什么测试集只能用一次？

测试集代表"模型从未见过的真实世界数据"。每用一次测试集做决策，测试集的客观性就降低一次：

```
第1次看测试集：真实水平
第2次看测试集：已经针对它调了一点 → 稍微偏高
第10次看测试集：几乎在迎合它 → 严重偏高
```

## 💡 关键理解

### 数据泄露（Data Leakage）

验证集和测试集必须**不能出现在训练集里**，否则模型"偷看"了答案：

```
❌ 错误做法：先合并所有数据，再随机划分
   → 可能有重复数据同时出现在训练集和测试集

✅ 正确做法：严格分离，训练集和测试集无交集
```

### 划分比例

| 数据量 | 常见划分 | 说明 |
|--------|---------|------|
| 大数据（百万级） | 98% / 1% / 1% | 数据多，1%也够评估 |
| 中等数据（万级） | 80% / 10% / 10% | 常见默认 |
| 小数据（千级） | 90% / 5% / 5% | 尽量多留训练数据 |

本项目（8,516条训练数据）的划分：

```
训练集: 7,664 (90%)  → 模型学习
验证集: 852 (10%)    → 训练过程中评估 + Early Stopping
测试集: 2,130        → HF 原始 test 集，训练过程中完全不碰
```

### 验证集 vs 测试集的本质区别

| | 验证集 | 测试集 |
|---|---|---|
| 训练过程中能看吗 | ✅ 能（但不参与梯度更新） | ❌ 绝对不能 |
| 能用来做决策吗 | ✅ 能（保存模型、早停、调参） | ❌ 不能 |
| 用几次 | 每个epoch用一次 | 训练结束后只用一次 |
| 客观性 | 中等（模型间接迎合了它） | 最高（模型没针对它做任何调整） |

## 🔧 代码实现

```python
from torch.utils.data import Dataset, DataLoader

# 划分 train / validation
train_texts = dataset['train']['title']
train_labels = dataset['train']['label']
split_idx = int(len(train_texts) * 0.9)  # 90% 训练，10% 验证

train_dataset = GubaDataset(train_texts[:split_idx], train_labels[:split_idx], word2id, MAX_LEN)
val_dataset = GubaDataset(train_texts[split_idx:], train_labels[split_idx:], word2id, MAX_LEN)
# 测试集完全独立，来自 dataset['test']
test_dataset = GubaDataset(dataset['test']['title'], dataset['test']['label'], word2id, MAX_LEN)
```

训练循环中的使用：

```python
for epoch in range(EPOCHS):
    # 训练阶段：只用训练集
    model.train()
    for batch_x, batch_y in train_loader:
        logits = model(batch_x)
        loss = criterion(logits, batch_y)
        loss.backward()

    # 验证阶段：用验证集做决策（保存模型 / 早停）
    model.eval()
    val_f1 = evaluate(val_loader)
    if val_f1 > best_val_f1:

        patience_counter = 0
    else:
        patience_counter += 1
        if patience_counter >= 5:

# 最终评估：只用测试集，只用一次

```

## ⚠️ 易错点与常见误解

1. **以为验证集没用，只有训练集和测试集就够了** → 没有验证集就无法做 Early Stopping 和调参决策，用测试集做决策会污染评估结果
2. **用测试集调参** → 测试集结果虚高，上线后效果大跌
3. **训练集和测试集有重叠** → 数据泄露，评估毫无意义
4. **验证集比例太大** → 训练数据不够，模型学不好
5. **以为验证集参与梯度更新** → 验证集只用于评估，不计算梯度，不更新参数

- Early Stopping — 验证集 F1 连续 N 轮不提升就停止训练，防止过拟合

- 过拟合与正则化 — 训练集效果很好但验证集/测试集效果差，说明模型在死记硬背
