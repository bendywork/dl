# 混淆矩阵：一眼看懂模型到底猜对了什么、猜错了什么

## 📌 核心问题
> 模型说"准确率 80%"，但它到底在哪些地方猜对了、哪些地方猜错了？混淆矩阵把模型的所有判断结果摆在你面前，一目了然。

## 🌱 根源与动机

### 准确率的欺骗性

假设 100 条帖子，90 条中性，5 条看多，5 条看空。模型**全猜中性**：

```
准确率 = 90/100 = 90%    ← 看起来很强！
看多的召回率 = 0/5 = 0%   ← 一个看多都没找到
看空的召回率 = 0/5 = 0%   ← 一个看空都没找到
```

**90% 准确率的模型，实际上对看多和看空完全无能。** 准确率被大类主导，掩盖了模型在小类上的失败。

混淆矩阵就是来解决这个问题的——**把每一个猜测结果摊开来看**。

---

## 📐 混淆矩阵是什么

### 一句话定义

> 混淆矩阵是一张表格，行是"真实标签"，列是"预测标签"，每个格子里填的是"有多少条数据落在这个组合里"。

### 二分类混淆矩阵

|  | **预测为正（看空）** | **预测为负（非看空）** |
|---|---|---|
| **实际为正（看空）** | TP ✅ | FN ❌ |
| **实际为负（非看空）** | FP ❌ | TN ✅ |

### 四个字母的含义（重点！）

```
T = True （猜对了）    F = False（猜错了）
P = Positive（正类）   N = Negative（负类）

第一个字母：对还是错
第二个字母：模型预测的是什么
```

| 缩写 | 全称 | 中文 | 通俗解释 | 例子 |
|------|------|------|---------|------|
| **TP** | True Positive | 真正例 | 实际是看空，模型也说是看空 | 🎯 **击中目标** |
| **FN** | False Negative | 假负例 | 实际是看空，模型说是非看空 | 🕳️ **漏掉了危险** |
| **FP** | False Positive | 假正例 | 实际非看空，模型说是看空 | 🚨 **误报，虚惊一场** |
| **TN** | True Negative | 真负例 | 实际非看空，模型也说是非看空 | ✅ **正确排除** |

### 记忆口诀

```
TP = 猜对了（T），猜的是正类（P）  → 命中
FN = 猜错了（F），猜的是负类（N）  → 漏网
FP = 猜错了（F），猜的是正类（P）  → 误报
TN = 猜对了（T），猜的是负类（N）  → 排除
```

**更快的方法：看第一个字母——T就是猜对了，F就是猜错了。** 就这么简单。

---

### 生活类比：火灾报警系统

```
真正着火，报警器响了   → TP  🎯 该报的报了（好）
真正着火，报警器没响   → FN  🕳️ 着火了没报（危险！人命关天）
没着火，报警器响了     → FP  🚨 假报警（烦，但不致命）
没着火，报警器没响     → TN  ✅ 正确安静（好）
```

**FN 最危险**——真着火没报出来，人命关天。
**FP 最烦人**——没着火老报假警，但不能不装报警器。

## 💡 从混淆矩阵推导出所有指标

### Precision（精确率）

```
Precision = TP / (TP + FP)
```

**含义：** 模型说"看空"的帖子中，真正看空的比例。

**类比：** 你报了 10 次火警，其中 3 次是真的 → Precision = 30%
- "你报的警，多少是真的？"
- **FP 越多，Precision 越低** → 模型在乱报

---

### Recall（召回率）

```
Recall = TP / (TP + FN)
```

**含义：** 真正看空的帖子中，模型找出来的比例。

**类比：** 总共着了 5 次火，你报了 3 次 → Recall = 60%
- "真正的危险，你发现了多少？"
- **FN 越多，Recall 越低** → 模型在漏报

---

### F1 Score（F1 分数）

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

**含义：** Precision 和 Recall 的调和平均。

**为什么不用普通平均？**

```
场景 A：Precision = 100%, Recall = 2%
  普通平均 = 51%  → 看起来还行
  F1 = 4%        → 暴露真相：几乎全漏了！

场景 B：Precision = 60%, Recall = 60%
  普通平均 = 60%
  F1 = 60%       → 两个都还行，F1 正常
```

**F1 对短板敏感——一个低就拉整体下来。** 这就是为什么用 F1 而不是普通平均。

---

### Accuracy（准确率）

```
Accuracy = (TP + TN) / (TP + FN + FP + TN)
```

**含义：** 所有预测中，猜对的比例。

**问题：** 当数据不均衡时，Accuracy 会骗人（见上文 90% 准确率但完全无能的例子）。

---

### 各指标对比

| 指标 | 关注什么 | 被什么拉低 | 什么场景最重要 |
|------|---------|-----------|--------------|
| **Precision** | 报警的准确性 | FP（误报） | 垃圾邮件过滤（别把正常邮件当垃圾） |
| **Recall** | 危险的覆盖率 | FN（漏报） | 癌症检测（别漏掉真正的癌症） |
| **F1** | 两者的平衡 | 任意一个低 | 通用评估（不想偏科） |
| **Accuracy** | 整体正确率 | 数据不均衡时失效 | 均衡数据的粗略评估 |

## 🔧 三分类混淆矩阵

实际项目中，股吧情感分析是三分类：看空(0)、看多(1)、中性(2)。

### 表格形式

|  | **预测看空** | **预测看多** | **预测中性** |
|---|---|---|---|
| **实际看空** | 50 ✅ | 10 ❌ | 30 ❌ |
| **实际看多** | 8 ❌ | 45 ✅ | 25 ❌ |
| **实际中性** | 15 ❌ | 20 ❌ | 97 ✅ |

### 怎么看？

**对角线**（左上到右下）是猜对的：50 + 45 + 97 = 192 ✅

**非对角线**是猜错的：10 + 30 + 8 + 25 + 15 + 20 = 108 ❌

**每一行**看一个真实类别的去向：
```
实际看空(90条)：50 猜对 + 10 被误判为看多 + 30 被误判为中性
  → Recall(看空) = 50/90 = 55.6%    漏掉了 44.4%
```

**每一列**看一个预测类别的来源：
```
预测看空(73条)：50 真的是看空 + 8 其实是看多 + 15 其实是中性
  → Precision(看空) = 50/73 = 68.5%  有 31.5% 是误报
```

### 混淆矩阵里的错误模式

| 错误模式 | 含义 | 严重程度 |
|---------|------|---------|
| 看空 → 看多 | 把看空判成看多 | 🔴 **最危险**：方向完全反了 |
| 看多 → 看空 | 把看多判成看空 | 🔴 **最危险**：方向完全反了 |
| 看空 → 中性 | 把看空判成中性 | 🟡 中等：至少没反 |
| 看多 → 中性 | 把看多判成中性 | 🟡 中等：至少没反 |
| 中性 → 看空/看多 | 把中性判成有方向 | 🟢 较轻：中性本来就模糊 |

**金融情感分析里，方向反了（看空→看多）比方向模糊（看空→中性）严重得多。** 看错方向会亏钱，看模糊只是少赚。

---

### F1-macro 是怎么算的

三个标签各算一个 F1，取平均：

```
看空:  TP=50, FP=23, FN=40  → Precision=68.5%, Recall=55.6% → F1=0.613
看多:  TP=45, FP=30, FN=33  → Precision=60.0%, Recall=57.7% → F1=0.588
中性:  TP=97, FP=55, FN=35  → Precision=63.8%, Recall=73.5% → F1=0.683

F1-macro = (0.613 + 0.588 + 0.683) / 3 = 0.628
```

**macro = 每个类权重相同。** 不管看空只有 90 条还是中性有 132 条，每个类的 F1 对最终结果的贡献一样。

## ⚠️ 易错点与常见误解

1. **以为准确率高就够了** → 数据不均衡时，全猜大类就能有高准确率，但小类完全无能

2. **混淆 TP 和 FP** → 记住口诀：第一个字母是"猜对还是猜错"，T=对，F=错

3. **混淆行和列** → 行=真实标签（上帝视角），列=模型预测（模型视角）

4. **以为 F1-macro 和 F1-micro 一样** →
   - macro：每个类各算 F1，取平均（小类和大类权重相同）
   - micro：把所有类的 TP/FP/FN 加在一起算一个全局 F1（大类主导）
   - 数据均衡时两者接近，不均衡时差异大

5. **以为 Recall 比 Precision 重要或反之** → 取决于场景：
   - 癌症检测：Recall 重要（不能漏）
   - 垃圾邮件：Precision 重要（不能误杀正常邮件）
   - 通用评估：F1 平衡两者

6. **以为 F1 越高越好，不看具体哪个类差** → F1-macro=0.68 可能是看空很差但中性很好拉上去的，要看每个类的具体情况

## 🔗 知识延伸

- [[模型训练数据划分]] — 训练集/验证集/测试集，验证集上算 F1 做决策
- ROC 曲线与 AUC — 另一种评估二分类的方式，画不同阈值下的 TPR vs FPR
- 交叉验证（K-Fold） — 数据少时，轮流当验证集，更可靠地估计模型性能
- 类别不平衡处理 — 过采样/欠采样/Focal Loss，解决大类压制小类的问题
