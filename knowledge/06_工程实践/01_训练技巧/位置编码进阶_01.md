# 位置编码进阶：RoPE 与 ALiBi

## 📌 核心问题
> 原始 Transformer 的 Sinusoidal 位置编码为什么不够用？RoPE 和 ALiBi 解决了什么？

## 🌱 根源与动机

**Sinusoidal 的问题**：
1. 绝对位置编码，模型学不到相对位置关系
2. 训练长度 < 推理长度时，泛化很差（长度外推问题）

现代 LLM 的两大主流方案：
- **RoPE**（Rotary Position Embedding）：旋转编码，用于 LLaMA/GPT-NeoX
- **ALiBi**（Attention with Linear Biases）：线性惩罚偏置，用于 BLOOM/MPT

## 📐 理论推导

### RoPE：旋转位置编码

核心思想：**将位置信息编码为 Q/K 向量的旋转**，使得 `QᵢKⱼᵀ` 只依赖相对位置 `i-j`。

2D 情况：
```
q' = q * e^{iθ}  （复数旋转）
k' = k * e^{iθ}
QKᵀ = Re[q * conj(k) * e^{i(θ_q - θ_k)}]
     = f(q, k, m-n)  ←  只依赖相对位置差 m-n
```

实现时拆成 sin/cos 对：
```python
# 对 [d1, d2] 做旋转
[d1*cos(θ) - d2*sin(θ), d1*sin(θ) + d2*cos(θ)]
```

**长度外推**：RoPE 可通过 NTK 插值/YaRN 动态调整频率扩展上下文窗口

### ALiBi：线性偏置

不改变 Q/K 编码，直接在 Attention Score 上加一个与距离成比例的负偏置：
```
Attention(Q,K,V) = softmax(QKᵀ/√d + m * [0, -1, -2, ..., -(n-1)])
```
其中 `m` 是每个 head 不同的斜率（头越多斜率越小）。

**优点**：训练短，推理长——线性惩罚天然支持长度外推，无需修改

## 💡 关键理解

| 方案 | 相对位置 | 长度外推 | 实现复杂度 |
|------|---------|---------|----------|
| Sinusoidal | ✗ | 差 | 简单 |
| RoPE | ✓ | 中（需插值扩展）| 中 |
| ALiBi | ✓ | 优秀 | 简单 |

- **RoPE 是当前主流**：LLaMA2/3、Qwen、Yi 等都用 RoPE
- **ALiBi 训推不一致**：不影响权重，推理时直接用更长序列即可

## ⚠️ 易错点与常见误解

1. **RoPE 只作用于 Q 和 K**，不作用于 V
2. **RoPE 旋转维度是成对的**：`(d1, d2), (d3, d4), ...`，必须偶数维
3. **ALiBi 的 m 是固定的**（按 head 数预设），不是可学习参数
4. 扩展上下文时 **YaRN 优于线性插值**，线性插值会降低高频分量精度
