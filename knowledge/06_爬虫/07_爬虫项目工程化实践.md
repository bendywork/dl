# 爬虫项目工程化实践

## 📌 核心问题
> 企业级爬虫项目如何管理配置、日志、任务调度和断点续传？如何让爬虫项目经得起生产环境的考验？

## 🌱 根源与动机

脚本型爬虫 vs 工程化爬虫的差异：

| 维度 | 脚本型爬虫 | 工程化爬虫（本项目） |
|------|-----------|-------------------|
| **配置** | 硬编码在代码里 | pydantic-settings 类型安全配置 |
| **日志** | print() | loguru 结构化日志 + 文件轮转 |
| **任务调度** | 手动运行 | APScheduler 定时任务 |
| **断点续传** | ❌ 中断后重来 | ✅ CheckpointManager JSON 检查点 |
| **依赖管理** | pip install 随手装 | pyproject.toml 版本锁定 |
| **环境管理** | 不知道，就这样跑的 | .env + .env.example + 多环境 |

## 📐 四大工程化组件

### 1. 配置管理 — pydantic-settings

项目使用 `pydantic-settings` 实现**类型安全的配置管理**：

```python
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",           # 从 .env 加载
        env_file_encoding="utf-8"
    )
    
    # 每个配置项都有类型声明 + 默认值
    mysql_host: str = "localhost"
    mysql_port: int = 3306
    crawl_concurrency: int = 10
    crawl_retry_times: int = 3
    crawl_request_delay: float = 0.5
    log_level: str = "INFO"

settings = Settings()
```

**为什么不用 `os.getenv()` 直接读？**

```python
# ❌ 原始方式：类型不安全、无默认值、无验证
host = os.getenv("MYSQL_HOST", "localhost")
port = int(os.getenv("MYSQL_PORT", "3306"))  # 如果值为 "abc" 会崩溃

# ✅ pydantic-settings：自动类型转换 + 验证
settings.mysql_port  # 永远是 int，来自环境变量或默认值
```

**`.env` 路径的可靠性处理：**

```python
# 关键：通过 __file__ 计算绝对路径，确保从任意目录启动都能找到 .env
_ENV_FILE = Path(__file__).resolve().parent.parent.parent / ".env"
```

**敏感信息管理：**

```
# .env（不提交到 Git）
MYSQL_PASSWORD=mylife@123
REMOTE_SERVER_TOKEN=2026shijian

# .env.example（提交到 Git，值用占位符）
MYSQL_PASSWORD=
REMOTE_SERVER_TOKEN=
```

### 2. 日志管理 — loguru

项目用 loguru 替代标准库 logging，API 更简洁：

```python
from loguru import logger

def setup_logger():
    logger.remove()  # 移除默认 handler
    
    # 控制台输出：带颜色、简洁格式
    logger.add(
        sys.stderr,
        level=settings.log_level,  # 从配置读取
        format="<green>{time:HH:mm:ss}</green> | <level>{level: <8}</level> | {message}",
    )
    
    # 文件输出：完整信息、自动轮转
    logger.add(
        settings.log_file,
        level="INFO",
        rotation="10 MB",        # 超过 10MB 自动轮转
        retention="7 days",      # 保留 7 天
        format="{time:YYYY-MM-DD HH:mm:ss.SSS} | {level} | {name}:{function}:{line} - {message}",
    )
```

**loguru vs logging 对比：**

```python
# 标准库 logging
import logging
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)
logger.info("处理了 %d 条数据，耗时 %.2f 秒", count, elapsed)

# loguru
from loguru import logger
logger.info("处理了 {} 条数据，耗时 {:.2f} 秒", count, elapsed)
# 不需要 getLogger，直接 import 就用
```

### 3. 任务调度 — APScheduler

爬虫需要定时运行（如每 10 分钟采集一次），项目使用 APScheduler：

```python
from apscheduler.schedulers.blocking import BlockingScheduler

def start_scheduler():
    service = AStockService()
    sched = BlockingScheduler()
    
    sched.add_job(
        service.sync_random_stocks_weekly,  # 执行函数
        "interval",                          # 触发类型：间隔
        minutes=10,                          # 每 10 分钟
        id="random_stocks_weekly",           # 任务 ID（用于管理）
        max_instances=1,                     # 最多同时运行 1 个实例
    )
    
    logger.info("📅 定时任务启动：每10分钟随机10只股票采集一周数据")
    sched.start()  # 阻塞主线程，持续运行
```

**APScheduler 触发方式：**

| 触发方式 | 用途 | 示例 |
|---------|------|------|
| `interval` | 间隔执行 | 每 10 分钟、每 1 小时 |
| `cron` | 定时执行 | 每天 9:30 开盘时 |
| `date` | 一次性 | 指定日期执行一次 |

### 4. 断点续传 — CheckpointManager ⭐

长时运行的爬虫最重要的可靠性保障：

```python
class CheckpointManager:
    """基于 JSON 文件的断点续传管理器
    
    存储结构：
    {
        "crawler": "flk_crawler",
        "source": "flk.npc.gov.cn",
        "created_at": "2026-06-12T10:00:00Z",
        "updated_at": "2026-06-12T11:30:00Z",
        "total_items": 150,
        "completed_items": 87,
        "completed_ids": ["id1", "id2", ...],
        "last_page": 8,
        "stats": {"success": 85, "failed": 2, "skipped": 0}
    }
    """
    
    def get_pending_ids(self, all_ids: List[str]) -> List[str]:
        """返回尚未完成的 ID 列表"""
        data = self.load()
        completed = set(data.get("completed_ids", []))
        return [i for i in all_ids if i not in completed]
    
    def mark_complete(self, item_id: str):
        """标记单个条目已完成"""
        data = self.load()
        completed = data.get("completed_ids", [])
        if item_id not in completed:
            completed.append(item_id)
        self.save({"completed_ids": completed, 
                    "completed_items": len(completed)})
```

**使用流程：**

```python
# 1. 启动时加载检查点
cpm = CheckpointManager("checkpoints/guba.json")
saved = cpm.load()

# 2. 只处理未完成的
all_posts = get_all_post_ids()
pending = cpm.get_pending_ids(all_posts)

# 3. 每完成一个就记录
for post_id in pending:
    scrape_post(post_id)
    cpm.mark_complete(post_id)  # 中断后从这里继续
```

## ⚠️ 易错点与常见误解

1. **硬编码密码** → 项目 `.env` 中还有个默认密码...生产环境绝不允许
2. **`.env` 提交到 Git** → `.env` 必须在 `.gitignore`，只提交 `.env.example`
3. **日志不设置轮转** → 爬虫连跑一个月，日志文件可能达到几十 GB
4. **print() 替代 logger** → 无法控制级别、无法输出到文件、无法追踪来源
5. **没有断点续传就上生产** → 爬了 3 天断了，因为没记录进度，必须从零开始
6. **忘记更新 `.env.example`** → 其他开发者拿到项目后不知道需要配置哪些变量
