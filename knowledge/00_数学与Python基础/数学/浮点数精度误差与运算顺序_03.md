# 浮点数精度误差与运算顺序

## 📌 核心问题
为什么向量化写法和循环写法结果 shape 一致，但数值有 1e-7 量级的微小差异？

## 🌱 根源与动机
两种写法逻辑等价，但计算机内部的运算顺序不同，而浮点数加法不满足结合律，导致累积误差。

## 📐 理论推导

差异来源：运算顺序不同

```
写法1：linear(token_embs)
→ 内部用 BLAS/cuBLAS 库，一次性做大矩阵乘法，运算顺序由库决定

写法2：循环逐token计算
→ 分5次做小矩阵乘法，每次独立累积误差
```

浮点数加法不满足结合律：
```python
(a + b) + c  !=  a + (b + c)   # 数学上相等，计算机里可能不等
```

IEEE 754 float32 精度：
- 只有 23 位尾数，约 7 位十进制精度
- 0.1 在二进制里是无限循环小数，只能截断存储
- 每次运算引入微小截断误差，多次运算累积 → 1e-6 ~ 1e-7 量级

## 💡 关键理解

这不是 bug，是正常的数值现象。
深度学习训练时学习率通常是 1e-3 量级，1e-7 的误差完全可以忽略。

判断两个张量"实际相等"应该用 allclose 而不是 equal：
```python
torch.allclose(out1, out2, atol=1e-6)  # True  ← 容忍范围内认为相等
torch.equal(out1, out2)                # False ← 严格逐元素相等
```

## 🔧 代码实现

```python
import torch
import torch.nn as nn

linear = nn.Linear(128, 256)
token_embs = torch.randn(1, 5, 128)

# 写法1：向量化
out1 = linear(token_embs)  # (1, 5, 256)

# 写法2：循环拼接
results = []
for i in range(5):
    xi = token_embs[:, i, :]                      # (1, 128)
    hi = xi @ linear.weight.T + linear.bias       # (1, 256)
    results.append(hi)
out2 = torch.stack(results, dim=1)  # (1, 5, 256)

# 结果对比
print(torch.equal(out1, out2))               # False ← 严格不等
print(torch.allclose(out1, out2, atol=1e-6)) # True  ← 误差在容忍范围内
print((out1 - out2).abs().max())             # 约 1e-7 量级
```

## ⚠️ 易错点与常见误解

1. 看到结果不 equal 就以为代码写错了 → 先用 allclose 判断，1e-6 内都是正常数值误差
2. 以为浮点数运算和数学完全一致 → 浮点数加法不满足结合律，运算顺序影响精度
3. float32 和 float64 误差量级不同 → float64 精度更高（15位），误差更小，但内存和计算开销更大

## 🔗 知识延伸
- 与 nn.Linear 向量化的关系：循环写法和向量化写法逻辑等价，但运算顺序不同导致浮点误差
- 与 torch.stack 的关系：循环结果需要在 dim=1 stack，补回被切片降掉的 t 维度
