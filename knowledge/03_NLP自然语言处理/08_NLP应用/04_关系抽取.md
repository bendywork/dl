# 关系抽取（Relation Extraction）

## 📌 核心问题
> 知道文中有哪些实体后，如何自动识别实体之间的语义关系？

## 🌱 根源与动机

NER 告诉你"有哪些实体"，RE 告诉你"实体之间是什么关系"：
```
"马云创立了阿里巴巴" → (马云, 创立, 阿里巴巴)
```
这是构建知识图谱三元组 `(Subject, Relation, Object)` 的核心步骤。

**关系抽取分类**：
- **Pipeline**：先 NER，再对实体对做关系分类（两阶段）
- **Joint**：NER 和 RE 同时预测（如 spert）

## 📐 理论推导

### Pipeline RE 思路

```
句子 → NER 找出所有实体对 (e₁, e₂) → BERT编码 → 关系分类头 → 关系类型
```

BERT 编码时会在实体两端加特殊标记：
```
"[E1]马云[/E1]创立了[E2]阿里巴巴[/E2]"
→ 取 [E1] 和 [E2] 的向量拼接 → FC → 关系类型
```

### Joint 抽取（spert 架构）

```
BERT → 
  ├─ Span分类：枚举所有span，判断实体类型（NER）
  └─ Span对分类：对实体span对，判断关系（RE）
两个任务共享BERT，端到端联合训练
```

**Span 枚举**：长度 1~max_span_size 的所有连续片段，加上位置特征、上下文特征

## 💡 关键理解

- **Pipeline 的问题**：错误在 NER 阶段会传播到 RE（误差级联）
- **Joint 的优势**：两个任务互相促进，NER 的实体信息有助于关系判断，反之亦然
- **关系分类是多分类**（含"无关系"类），正负样本高度不均衡，需要负采样或 Focal Loss
- **嵌套实体的关系**：spert 的 span 方式天然支持嵌套

## ⚠️ 易错点与常见误解

1. **RE 的标签是有向的**：(A, 创立, B) ≠ (B, 创立, A)，数据标注需要明确主客
2. **实体对的爆炸式增长**：n 个实体有 n(n-1) 对，需要负采样控制训练集规模
3. **远程监督（Distant Supervision）噪声**：用知识库自动对齐文本标注，噪声大，需要去噪
4. **跨句关系**：实体在两个不同句子中，需要文档级 RE 模型（如 DocRED 数据集）
