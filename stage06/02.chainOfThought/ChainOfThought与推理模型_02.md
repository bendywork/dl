# Chain of Thought 与推理模型

## 一、什么是 Chain of Thought (CoT)

### 直觉

人类解复杂问题不会直接蹦答案，而是会在脑中推几步。CoT 就是让模型也这样做：

```
没有 CoT：
  Q: 小明有 5 个苹果，给了小红 2 个，又买了 3 个，还剩几个？
  A: 6 个                                   ← 可能对，可能错

有 CoT：
  Q: 小明有 5 个苹果，给了小红 2 个，又买了 3 个，还剩几个？
  A: 小明一开始有 5 个。
     给了小红 2 个后：5 - 2 = 3 个。
     又买了 3 个后：3 + 3 = 6 个。
     所以还剩 6 个。                         ← 正确率大幅提升
```

### 为什么 CoT 有效

标准 Decoder 是逐 token 生成的。如果没有中间推理步骤，模型需要在第一个输出 token 之前"在心里"一次性完成所有计算，这受限于模型的层数。

CoT 把计算展开到输出序列中，等于用**额外的 token 换取额外的计算步骤**。每一步的输出成了下一步的输入，形成递进推理链。

```
没有 CoT：层数层计算 → 被迫压缩
有 CoT：  层数层计算 → 输出中间结果 → 再输入 → 继续计算
          输出 token 变成了"草稿纸"
```

## 二、CoT 的使用方式

### 方式 1：Few-shot CoT

在 prompt 里给推理示例：

```
Q: 餐厅有 23 张桌子，每张坐 4 人，已经有 56 人入座，还能坐多少人？
A: 总座位 = 23 × 4 = 92
   已用 = 56
   剩余 = 92 - 56 = 36
   还能坐 36 人。

Q: {用户的问题}
A:  ← 模型模仿上面的格式输出推理链
```

### 方式 2：Zero-shot CoT

加一句魔法咒语："Let's think step by step."

```
Q: {问题}
Let's think step by step.
  ← 模型自动展开推理
```

### 方式 3：自动 CoT (Auto-CoT)

不要人写示例，让模型自己为不同问题聚类生成推理链，再作为示例。

### 效果差异

| 方法 | GSM8K (数学) | StrategyQA (推理) |
|------|-------------|-------------------|
| 标准 Prompt | ~18% | ~65% |
| Zero-shot CoT | ~41% | ~73% |
| Few-shot CoT | ~58% | ~76% |

## 三、CoT 的变体

### Self-Consistency (自一致性)

跑 N 次 CoT，取出现最多的答案。相当于"多数投票"。

```
同一问题 → CoT 推理 × 5
  路径 1: ... → B
  路径 2: ... → B
  路径 3: ... → A
  路径 4: ... → B
  路径 5: ... → B
最终答案：B（4/5票）
```

### Tree of Thoughts (ToT)

不只推一条链，而是**分支探索 + 回溯**。像下棋一样评估每一步。

```
          问题
       /    |    \
     步1   步1'  步1''
     / \    |    / \
   步2 步2' 步2'' ...
    ↑
  评估每个分支 → 剪枝 → 深入探索 → 回溯
```

### Graph of Thoughts (GoT)

比 ToT 更进一步，允许多条思维链**合并**，形成有向图：

```
链A: 分析角度1 → 结论A
链B: 分析角度2 → 结论B
         ↘      ↙
        合并 → 综合结论
```

### ReAct (Reasoning + Acting)

交错推理和行动。不是先想完再做，而是一边想一边做：

```
Thought: 我需要先查北京的天气
Action: search("北京天气")
Observation: 北京今天 25°C，晴
Thought: 天气适合户外活动，推荐故宫
Action: 最终回答
```

## 四、推理模型 (Reasoning Models)

### 从 Prompt Engineering 到内置推理

前面的 CoT 都是**外部 Prompt 技巧**——模型本身没有推理能力，你提示它怎么想它才怎么想。

2024 年起，模型开始**内置推理**：不用你教，它自己就该多想就多想。

### 代表模型

**OpenAI o1 (2024.09)**

```
特点：
  - 内部产生隐藏推理链（hidden reasoning chain）
  - 用户只看到推理摘要，看不到完整过程
  - 推理时间越长 → 答案质量越好
  - 数学/代码/科学推理能力显著跃升

原理：RL 训练 + Chain-of-Thought 作为内部过程
不足：慢（几秒到几分钟）、贵、隐藏推理 token 也收费
```

**OpenAI o3 (2024.12)**

```
o1 的升级版，推理能力更强，支持可调节推理时间
```

**DeepSeek-R1 (2025.01)**

```
特点：
  - 开源，MIT 协议
  - 用 GRPO (Group Relative Policy Optimization) 训练
  - 推理过程完全可见（你能看到它怎么想的）
  - 性能比肩 o1，成本极低
  - 出现"顿悟时刻"(Aha moment)：模型自己学会了停下来反思

训练方法：
  1. DeepSeek-V3 基座
  2. 少量高质量 CoT 数据做冷启动 SFT
  3. RL (GRPO)，用正确性作为奖励信号
  4. 拒绝采样 + 更多 SFT 数据
  5. 最终 RL 阶段
```

### 推理模型 vs 普通模型

| | 普通 LLM | 推理模型 |
|------|----------|----------|
| 回答问题 | 直接输出 | 内部推演后输出 |
| 耗时 | 快（<1秒） | 慢（几秒~几分钟） |
| 简单问题 | 很好 | 过度思考，浪费 |
| 复杂推理 | 容易出错 | 大幅提升 |
| 最佳场景 | 闲聊、翻译、摘要 | 数学、编程、科学、逻辑 |

### 推理时计算 (Inference-Time Compute)

关键认识转变：

```
旧思路：模型大小决定智能 → 加大参数量
新思路：推理计算量决定智能 → 不加大模型，推理时多算几步

o1 的成功证明了：
  推理时的额外计算（内部推理链）比增加参数量更高效
```

## 五、CoT/推理的技术总结

### 演进路径

```
2022: Prompt CoT (Few-shot / Zero-shot)
        └── 外部提示，模型跟随格式

2023: Self-Consistency / ToT / ReAct
        └── 多次采样 + 分支探索 + 行动交错

2024: o1 推理模型
        └── 内部隐藏推理链，RL 训练内置思考

2025: DeepSeek-R1, o3
        └── 开源追赶，可调节推理时间，GRPO 训练
```

### 为什么推理模型是重大转折

之前：模型能力 = 训练时投入（数据 × 参数 × 计算）

现在：模型能力 = 训练时投入 + 推理时投入（额外推理 token）

这意味着**同样的模型**，只给它更多推理时间，它在困难任务上就会变聪明。这和人类考试一样——多给你 10 分钟，你就能把难题解出来。
